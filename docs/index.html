謝罪応答の受け手シミュレータ

誠実に見える謝罪のかたち、つまり受け手に「釣り合っている」と感じさせる振る舞いとは何かを、受け手の多様さを含めて測るツールです。

AIアシスタントの謝罪、AIキャラクターの謝罪、物語の登場人物の謝罪を扱います。

SHAZAI Rules で、一般的なペルソナ型の LLM Judge が人間の評定をまったく再現できなかった（一般的なチェックリストの方がまだ傾向を反映した）ため、人間の評定により近づけることを目的に作りました。Claude Opus 5.5 で作成しています。

肩に乗った羊として

システムに組み込むと、このシミュレータは肩に乗った羊のように働きます。AIが失礼な応答をしたとき、その場で「メッ！」と鳴いて知らせる、AIに欠けている「自覚」の代わりです（組み込み判定モード sim.py check。詳細）。

謝り方そのものを整えるのが SHAZAI Rules、その謝り方が相手に届いたかを確かめるのがこのシミュレータです。併用を推奨します。

二つの層に分ける

LLMのペルソナに「日本人として評定して」と頼む方法はとりません。評定を二つの層に分けます。

会話・場面・回答ベンチマークの回答、物語やAIキャラクターの場面
→
層A 観察（LLM）何が書かれ、何が描写されているかを記録するだけ。良し悪しは判断しない（observe_prompt.md）
→
層B 受け手（コード）研究で効く向きが示された性質をもつ受け手の母集団に、観察を通す（sim.py・population.json）
→
評定の所属度回答ごとの4つの述語の平均所属度、失礼と感じる人の割合、無礼さ・不足・過剰の量

評定はファジィです。受け手一人ひとりが、4つの述語それぞれにどの程度当てはまると感じるか（所属度 0〜1）を持ちます。述語は排他的ではなく、「重すぎるのに足りない」「少し失礼だが、だいたい釣り合う」も表せます。人による違いは母集団（確率）が、一人の中の程度は所属度（ファジィ）が担います。

失礼

無礼さ（失点の合計）から。一文や一つの振る舞いだけでも高くなる

足りない

謝罪の中身の不足量（受け手が必要とする深さとの差）から

釣り合う

失礼でなく、足りなくなく、重すぎない（三つの否定の論理積）

重すぎる

重さが受け手の許容を超えた量から

現在の到達点

ベンチマーク（SHAZAI Rules v0.4、192回答・16場面）で、シミュレータの予測分布を真に適正なスコアリング規則（Brier）で、場面単位の交差検証の外側で採点しています。代理観察で Brier 0.489、観察者の集団（6変種）の平均に出どころの較正を加えた LLM の観察で 0.489 で、「条件だけ」の基準（0.553）に対するスキルは +0.115〜+0.116 です。区間はわずかに 0 をまたぎます。「常に釣り合う」の基準（0.719）は、どの評価器にも負けます。条件の順位は筆者と一致し、LLM ペルソナの評定では逆になります（筆者との一致度 κ は、代理観察 0.33、ペルソナ 0.06）。

場面単位の4分割交差検証の分割の外側で採点した Brier（低いほど良い）。[ ] は95%区間。詳細は 検証結果 3章

受け手モデルは、謝罪を失敗の前・謝罪の場面・修復期の時間の中で見ます。修復期は詫びではなく控えで測り、失敗の前の構えと免責の但し書きの局面も受け手モデルに入れています。信頼の傷は20ターンで減衰すると仮定しています。人間の評価キット（ラテン方格、事前登録した仮説の検定、検出力）もあります。

型の比率、性質の強さ、所属度関数、控えの時間軸の係数はいずれも事前値で、人間のデータで推定していません。詳細は 検証結果 と 総合評価、経緯は 履歴 にあります。

使い方

Python 3.9 以上、標準ライブラリのみで動きます。runs/* は apology-benchmark の実行先ディレクトリ（manifest.json を含む）です。

  1. 層A：観察する 
    # LLMで観察する（OpenRouter。環境変数 OPENROUTER_API_KEY が必要。中断後は同じコマンドで再開）
python3 sim.py observe runs/* -o out/obs-llm.json --model anthropic/claude-opus-5.5

# API を使えない場合：既存のチェックリスト判定と表層特徴から代理観察を作る
python3 sim.py proxy runs/* -o out/obs-proxy.json

# 観察者の集団。文に ID を振り、観察方針を変えて観察し、平均する
python3 sim.py segment runs/* -o out/segment.json
python3 sim.py observe runs/* --segment out/segment.json --variant literal -o out/obs-literal.json
python3 sim.py ensemble out/obs-literal.json out/obs-context.json out/obs-neutral.json -o out/obs-ensemble.json
  2. 層B：母集団に通す 
    # 母集団で評定の所属度を出す
python3 sim.py simulate out/obs-llm.json runs/* -n 1000 -o out/sim.json

# 観察済みの場面の組（物語・AIキャラクター等）を母集団に通す
python3 sim.py scenes examples/scenes.json -n 1000 -o out/scenes-result.json

# 控えの時間軸の項目の組（失敗の前の構え・修復期・但し書きの局面）
python3 sim.py scenes examples/scenes-kit.json -o out/scenes-kit.json
  3. 読み解く 
    # 1人の評定者（user-ratings.json）を最もよく再現する θ を探す
python3 sim.py fit out/obs-llm.json runs/* --trials 4000 --seed 7 -o out/fit.json

# 1回答について、型ごとの評定とその理由を見る
python3 sim.py explain out/obs-llm.json runs/* --answer 回答ID
  4. 評価する 
    # 真に適正なスコアリング規則による評価（場面単位の交差検証、基準とスキルスコア）
python3 tools/evaluate.py runs/* --obs proxy=out/obs-proxy.json --obs llm=out/obs-llm.json -o out/eval.json

# 人間の評価キット（ラテン方格の問題束、事前登録した仮説の検定、検出力）
python3 blind.py pack --design --scenes examples/scenes-kit.json --repeat 2 --out-dir human/kit
python3 blind.py power --scenes examples/scenes-kit.json --hypotheses human/hypotheses.json --raters 20,40,60

# 総合評価の再現
sh tools/run_eval.sh
  5. （オプション）1ターンをその場で判定する 
    # 1ターンを System One（Jev）で観察して即座に判定する組み込み用モード
# 環境変数 TYPESAFE_API_KEY が必要。--backend llm-s1 で互換モード（OPENROUTER_API_KEY）
python3 sim.py check examples/check/turn.json

    hook などでAIの応答を毎ターン判定する仕組みの参考として用意した組み込み用モードです。1ターンにつき System One モデルを1回呼び、結果を母集団に通して「失礼の恐れ／要注意／問題なし」と、失礼の度合いに応じた羊の鳴き声（「メ…？」「メッ」「メッ！！」）を返します。Claude Code の Stop hook の例は examples/hooks/shazai_stop_hook.py にあります。Jev の実際の応答では未検証です。詳細は 層AのJevへの置き換え 5.8節。

共通の選択肢

選択肢働き
--no-hysteresis信頼損傷ヒステリシス（経緯で受け取り方が変わる）を無効にする。既定は有効
--no-escalation一段改めた謝罪も割り引く。既定は割り引かない。ヒステリシスが有効なときだけ効く
--seed乱数の種
-n受け手の数

観察者には、評価対象とは別系統のモデルを使うのが安全です。

人間のブラインド評定と自動評価の比較

# 評定用の問題束と評定ページを作る（rate.html を評定者に渡す。key.json は渡さない）
python3 blind.py pack --scenes examples/scenes.json --repeat 4 --out-dir human/s01

# 集めた評定ファイルと、シミュレータ（や他の自動評価）の差を測る
python3 blind.py compare --key human/s01/key.json --ratings "human/s01/ratings/*.json" \
    --sim out/scenes-result.json --auto persona=persona.json \
    --scenes examples/scenes.json --rater-types -o human/s01/compare

評定ページは1枚のHTMLで、ブラウザで開くだけで使えます。評定者は、各返答に「失礼だ」「足りない」「重すぎる」「釣り合っている」がそれぞれどのくらい当てはまるかを5段階で答えます。条件やラベルは伏せられ、出題順は評定者ごとに変わります。同じ項目を後半にもう一度出して、個人の評定の安定性も測ります。

比較の結果には、人間どうしの一致を上限の目安として並べ、次の項目を報告します。

  • 所属度の近さ
  • 述語ごとの差と相関
  • 偏りの向き
  • 「釣り合う」の構成の検証
  • 場面の種類ごとの差
  • 評定者ごとに最も近い型

詳細は 人間のブラインド評定 を参照してください。

何を扱えるか

謝罪の言葉

冒頭か過失を具体的に言う負担を言う弁解条件付き相手への指摘先を急ぐ装飾

一文ごとの悪い読み

怒っている相手には、その一文がどう聞こえるか

身体のシグナル

しょんぼりバツが悪そう視線を落とす言葉数が減る赤面涙ショックお辞儀土下座

食い違いと代償

笑み「てへっ」修復の行動補償自分の何かを差し出す宣言だけの代償

場面の枠組み

現実のタスク／物語AIアシスタント／AIキャラクター／登場人物本人／第三者過失が明白／曖昧上下と親疎

経緯

指摘の回数受け入れた後か過去の謝罪の回数破られた約束

AIのト書きや顔文字は「仮想の身体」として扱います。現実のタスクでは受け取り方が人によって大きく分かれ、失敗が深刻なほど効きが落ちます。物語の中では、作中の身体として読まれます。
