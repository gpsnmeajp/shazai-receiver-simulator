# 総合評価（v0.8、2026-11-19）

v0.8（ファジィ前提）の実装を、ベンチマークと作例で総合的に評価した記録です。外部の LLM API を使う部分は、**Claude のサブエージェントで代替**しました。評価の数値と判明した欠陥をまとめます。設計は [DESIGN.md](DESIGN.md)、検証の経緯は [VALIDATION.md](VALIDATION.md) を参照してください。

## 1. 要点

1. **代理観察（LLM なし）では、v0.8 は v0.7 と同等以上です。** 筆者の4値の評定との一致度は κ 0.33（95% 区間 0.20〜0.47、192件中128件一致）で、v0.7 は同じ観察で 0.31〜0.32 でした。条件の順位（指示なし < 一般的な謝罪指示 < SHAZAI Rules）は筆者と一致しています。LLM ペルソナ（κ 0.04〜0.11）より明確に高い値です。
2. **本来の層A（LLM の観察。今回はサブエージェント）を通すと、シミュレータは厳しすぎます。** κ 0.28（区間 0.18〜0.38）で、「釣り合う」の平均所属度が全条件で筆者より 0.14〜0.24 低くなりました。条件の順位は保たれています。
   - 回答の観察が「失礼」を押し上げる（平均所属度 24 → 40）
   - 場面の観察が不満の深さを上げ、「足りない」を押し上げる（25 → 35）
3. **修復期の論理に欠陥があります（v0.8 で表面化）。** 謝罪がすでに受け入れられた後、詫びを繰り返さないのは正しい振る舞いです。それなのに受け手モデルは、必要な中身との差を「不足」として数えます。サブエージェント観察では修復期の一致が 0.33（代理観察 0.79）に落ちました。
4. **v0.8 の評価指標「近さ」（1 − 平均絶対差）には欠陥があります。** 正解が4値のとき、最頻の評定を断定的に出すほど得をします。実際、「常に釣り合う」と答えるだけの評価器が近さで最良（0.820）になり、LLM ペルソナもシミュレータを上回りました。二乗誤差（Brier）では順位がまともになります（シミュレータ 0.536 < 常に釣り合う 0.719 < ペルソナ 0.84〜0.91）。`fit` の目的関数も同じ指標を使っています。
5. **System One 経路（`check`）は動作しました。** サブエージェントを System One 互換の判定器として、12回答・1,898問を判定させ、観察を組み立てて母集団に通せました。筆者との一致は 6/12（代理観察は 7/12）で、件数が少なく優劣は言えません。
6. **観察者の一致（作例23問、サブエージェント対手の観察）について。**
   - 場面の枠組み（5/5）と、詫びの有無・位置（23/23）は完全に一致しました。
   - 一文ごとの悪い読みは、手の観察にない読みを良い回答にも 0.4〜0.6 で付けます。所属度のずれの多くはここから来ます。

## 2. 方法

| 役割 | 本来の担い手 | 今回の代替 |
|---|---|---|
| 層A 観察（`observe_prompt.md`） | OpenRouter の LLM（`sim.py observe`） | サブエージェント8体（1体あたり8場面・24回答）。盲検（会話と回答の本文だけを渡し、条件・モデル名・評定は渡さない。入力以外のファイルを開かないよう指示） |
| 作例の観察 | 同上 | サブエージェント1体（5場面・23回答）。既存の手の観察は見せない |
| System One 判定器（`check`） | TypeSafe の Jev | サブエージェント4体（12回答、計1,898問）。質問ごとに独立に確率で答える |
| 人間の評定 | 筆者の4値の評定（ベンチマーク付属） | そのまま使用。人間の代わりはサブエージェントにさせない（ペルソナ評定が失敗した経緯があるため） |

- データ：SHAZAI Rules リポジトリの `supplement/apology-benchmark_example/runs/`（4モデル × 3条件 × 16場面 = 192回答、筆者の評定、LLM ペルソナ3名の評定）。
- 観察者は、組み立て用のスクリプトで JSON を書き出しました。中身は判断した値を書き込んだ辞書で、正規表現は文の分割にだけ使っています（スクリプトを確認済み）。
- 受け手は1000名、乱数の種は7です。1000名なら、種1〜10で κ は ±0.01 しか動きません（500名では最大 0.05 ずれることがありました）。
- 区間は、場面単位のブートストラップ（1000回）による 95% 区間です。同じ場面の回答は独立でないため、場面単位にしています。
- 道具は `tools/evaluate.py`（評価）と `blind.py compare`（人間評定の比較の流れ）です。データは `eval/` にあります。
- **注意：観察者のサブエージェントは Claude Opus 5.5 で、評価対象のモデルの一つ（claude-opus-5.5）と同系統です。** README は観察者に別系統のモデルを勧めています。

## 4. サブエージェント観察が厳しくなる理由

場面の観察と回答の観察を、代理観察と入れ替えて組み合わせました（受け手500名）。

| 場面の観察 | 回答の観察 | 平均所属度（失礼 / 足りない / 釣り合う / 重すぎる） | 不満の深さの平均 |
|---|---|---|---|
| 代理 | 代理 | 24 / 25 / 59 / 7 | 2.48 |
| 代理 | サブエージェント | **40** / 23 / 49 / 8 | 2.48 |
| サブエージェント | 代理 | 26 / **35** / 51 / 6 | **2.76** |
| サブエージェント | サブエージェント | 42 / 34 / 42 / 7 | 2.76 |

- **回答の観察**：筆者が「釣り合う」とした回答で、サブエージェント観察の主な失点は、悪く読める一文 0.13、依頼の未遂行 0.13、先を急ぐ 0.12、誤りの上塗り 0.07 でした。代理観察では、どの失点も 0.07 以下です。
- **場面の観察**：64場面の合計で、サブエージェントは代理観察より、距離の変化を +12、損害を +10、過去の指摘を +7 多く読みました。
- **一文の悪い読みの切除**：1,521文のうち369文に読みが付き、自然さ 0.5 以上は68文でした。読みを全部外しても、κ は 0.29 → 0.31、「釣り合う」は +0.03〜0.04 しか変わりません。厳しさの主因は一文の読みではありません。

## 5. 修復期の欠陥

| 観察 | 受け入れ後と記録 | 回答に詫びあり | 不足の平均 | 平均所属度（失礼 / 足りない / 釣り合う） | 筆者 |
|---|---|---|---|---|---|
| 代理 | 24/24 | 1/24 | 0.66 | 5 / 30 / 68 | 釣り合う 19、足りない 3、失礼 2 |
| サブエージェント | 24/24 | 1/24 | **1.37** | 16 / **57** / 40 | 同上 |

受け入れ後の必要な中身を `min(need, 1 + 0.8·傷)` として残しているため、詫びを繰り返さない正しい回答でも不足が残ります。傷はサブエージェントが過去の指摘を多く読むほど深くなり、「足りない」が上がります。v0.7 では、不足に 0.8 を掛けてから閾値 1.0 で判定していたため、隠れていました。

**修正の方向**：受け入れ後は、謝罪の言葉の不足を数えない（必要な中身を、謝罪の言葉ではなく依頼の遂行と態度で満たすものにする）。破った約束がある場合だけ、改めた謝罪を求めます。

## 6. 評価指標の欠陥（D-016 の見直し）

人間の評定の比較の流れ（`blind.py compare`）に、筆者の評定を「人間」側として、各評価器を自動評価として並べました。指標によって、評価器の順位が逆転します。

| 評価器 | 近さ（1 − MAE） | Brier（二乗誤差の和） | 対数損失（正規化） | 最大所属度が筆者と一致 |
|---|---|---|---|---|
| v0.8・代理観察 | 0.758 | **0.536** | **0.949** | **0.67** |
| v0.8・サブエージェント観察 | 0.720 | 0.677 | 1.136 | 0.56 |
| ペルソナ P1 / P2 / P3 | 0.773 / 0.781 / 0.789 | 0.906 / 0.875 / 0.844 | 3.13 / 3.03 / 2.92 | 0.55〜0.58 |
| 常に「釣り合う」 | **0.820** | 0.719 | 2.49 | 0.64 |
| 参照：条件ごとの筆者の評定頻度 | 0.747 | 0.506 | 0.889 | 0.64 |

- 平均絶対差を最小にするのは中央値で、一点集中の正解に対する中央値は最頻値です。そのため「近さ」は、最頻の評定を断定的に出す評価器を有利にします。v0.8 で主指標にした「項目平均との近さ」と `fit` の目的関数は、この偏りを持っています。人間の評定がファジィ（5段階）でも、評定が偏った項目では同じことが起こります。
- 二乗誤差は平均で最小になるので、所属度を正直に出す評価器を不利にしません。**主指標を二乗誤差に替え、比較表に定数の予測（常に釣り合う、人間の平均所属度）を自動で並べるべきです。**
- 参照の「条件ごとの筆者の評定頻度」は筆者の評定そのものから作った値なので、公平な比較相手ではありません。それでも、シミュレータの Brier（0.536）がこれ（0.506）に届いていないことは、場面ごとの違いを読む力がまだ弱いことを示しています。
- 項目間の相関では、シミュレータがペルソナを大きく上回ります（代理観察：失礼 0.48、釣り合う 0.42。ペルソナ：失礼 0.23〜0.32、釣り合う 0.05〜0.20）。

## 7. 所属度関数の感度（代理観察 / サブエージェント観察の κ）

| 設定 | 代理観察 | サブエージェント観察 |
|---|---|---|
| 既定（失礼 1.2/0.3、足りない 1.0/0.3、重すぎる 0.3/0.25、min） | 0.33 | 0.28 |
| 失礼の中心 1.5（最初に置いた値） | 0.31 | **0.31** |
| 失礼の中心 1.0 | 0.33 | 0.24 |
| 足りないの中心 0.8 | **0.26** | 0.28 |
| 足りないの中心 1.25 | 0.33 | 0.26 |
| なだらかさ ×0.5（4値に近い） | 0.32 | 0.28 |
| なだらかさ ×2 | 0.33 | 0.29 |
| 釣り合う＝積 | 0.32 | 0.28 |
| 境界をほぼ段差に（0.05） | 0.33 | 0.28 |

- 結果は、なだらかさ・t ノルム・境界の形にはほとんど左右されません。効くのは中心の位置です。
- 失礼の中心の最適値は、観察の厳しさで変わります（代理観察では 1.0〜1.2、サブエージェント観察では 1.5）。所属度関数は観察者ごとに較正する必要があります。作例を見て 1.2 に下げた調整（[VALIDATION.md](VALIDATION.md) 2.1）は、厳しい観察者では逆効果でした。
- ヒステリシスの有無：代理観察 0.33 / 0.33、サブエージェント観察 0.28 / 0.32（なしの方が高い）。傷が深く読まれると、修復期の欠陥（5章）が強く出るためです。

## 9. System One 経路（`check`、12回答）

gpt-6.1-sol の4場面（段階 1・3・4・修復期）× 3条件を、サブエージェントの判定器で答えさせました。

- 12回答・1,898問すべてに答えがそろい、`replay` で観察を組み立てて母集団に通せました。真偽の質問の確率は 0.01〜0.05 に集中していて（各文に「詫びか」「弁解か」を問うので、多くは「いいえ」）、中間の値も付いています。
- 筆者との一致：System One 経路 6/12、代理観察 7/12。筆者の評定の述語への所属度：0.49 / 0.46。
- 修復期の3回答は、どちらの観察でも、条件によらず同じ所属度（System One 経路では足りない 52・釣り合う 48）になりました。5章の欠陥と同じ現象です。

## 10. 筆者への当てはめ（`fit`）

| 観察 | 学習 κ | 検証 κ | 最も近い型 |
|---|---|---|---|
| 代理観察 | 0.31 | 0.29 | 寛容・観察者型（3.5）、当事者・関係修復型（3.6） |
| サブエージェント観察 | 0.35 | **0.35** | 寛容・観察者型（3.1）、礼節規範型（3.5） |

サブエージェント観察では、筆者に合わせた θ で検証 κ が 0.35 になり、母集団の既定値（0.28）を上回りました。観察の厳しさを、θ（寛容さ寄り）が吸収した形です。目的関数は6章の欠陥を持つ「近さ」なので、この数値も割り引いて読む必要があります。

## 11. 限界

- 人間の評定は筆者1名・4値だけです。ファジィな人間の評定（5段階）はまだありません。
- 観察者は Claude Opus 5.5 の1系統・1回だけです。同じ観察を繰り返したときの再現性は測っていません。評価対象のモデルの一つと同系統です。
- 代理観察の規則と場面の事実は、筆者の評定を見ながら作られています（[VALIDATION.md](VALIDATION.md) 3章）。代理観察の κ は甘めです。
- System One 経路は12回答だけで、Jev 本体ではなく、サブエージェントによる代替です。
- 失礼の中心 1.2 は作例を見て決めた値です。

## 12. 推奨する修正（優先順）

1. **修復期の論理を直す**（5章）。受け入れ後は謝罪の言葉の不足を数えない。
2. **評価指標を直す**（6章）。`blind.py compare` の主指標と `fit` の目的関数を二乗誤差にし、定数の予測（常に釣り合う、人間の平均所属度）を自動で比較表に並べる。D-016 を改める。
3. **所属度関数を観察者ごとに較正する**（7章）。`judgment` を観察の出どころ（代理／LLM／System One）ごとに持てるようにし、少数の人の評定で中心を合わせる。
4. **観察の厳しさを測る**。同じ回答を観察者に2回観察させて再現性を測り、別系統のモデルの観察とも比べる。
5. **筆者（と他の人）の評定を5段階で取り直す**。4値の正解では、ファジィな出力の良し悪しを十分に測れない。
