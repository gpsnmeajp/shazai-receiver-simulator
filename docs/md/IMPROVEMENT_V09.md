# v0.9 改善の設計

[EVALUATION.md](EVALUATION.md)（v0.8 の総合評価）で見つかった問題を直すための設計です。柱は次の三つです。

1. 「控え」を観察する。失敗の前の構え（控えめに言っていたか、断言していたか）を信頼の傷に入れ、修復期は詫びではなく控えの不足を測る
2. 評価指標を、統計的に正当なもの（真に適正なスコアリング規則、交差検証、場面単位の不確かさ）に改める
3. 層Aの観察を、観察方針と前提に幅を振った複数の観察（観察者の集団）の平均にする

あわせて、観察者ごとの較正、場面の観察の厳しさ、人間のデータの集め方も見直します。

状態：**設計（未実装）**。2026-11-19 作成。

## 1. 控え：失敗の前の構えと、修復期のふるまい

控えは、失敗の後だけの問題ではありません。失敗の前にどれだけ控えていたか（自信なく控えめに言っていたのか、自信満々だったのか、断言して強気だったのか）も、その後の謝罪の効き方を変えます。1.1〜1.5節は失敗の後（修復期）、1.6〜1.10節は失敗の前の構えです。両者は、信頼の傷（ヒステリシス）と控えの必要量を通じてつながります。

### 1.1 問題

v0.8 は、謝罪を受け入れた後（修復期）でも、謝罪の言葉の不足を「必要な中身との差」として数えていました。修復期に詫びを繰り返さないのは正しい振る舞いです。筆者の評定でも、修復期の24回答のうち19件が「釣り合う」で、その23件には詫びの言葉がありません。それなのにモデルは「足りない」を出していました（LLM の観察で修復期の一致 0.33）。

### 1.2 考え方：謝罪は出来事、控えは状態

謝罪は一度の出来事です。受け入れられた後に相手が見ているのは、もう一度の謝罪ではなく、**その後のふるまいに反省が表れているか**です。日本語でいえば「わきまえる」「慎む」「調子に乗らない」です。受け入れた側にとって、詫びの繰り返しはむしろ負担になります（「もう謝らなくていいのに」）。一方で、受け入れた直後に何もなかったように軽い調子に戻ると、「反省していない」と受け取られます。

つまり修復期の受け手が求めるのは、**控え**です。

- **抑え**：調子を急に戻さない。はしゃがない。冗談にしない。許されたことを当然視しない。
- **配慮**：確認を一つ挟む。慎重な言い回しにする。相手の手間を減らす。
- **一貫**：前に約束したことを、このターンで実際に守っている（「削除の前に確認する」と言ったなら、確認している）。
- **過剰でない**：詫びを繰り返さない。事件を必要以上に蒸し返さない。

控えの必要量は、信頼の傷（ヒステリシスの S）が深いほど大きくなります。軽い失敗の後なら、ほぼ普段どおりで足ります。誠実さの違反や約束の破りの後なら、しばらくは控えが目に見える必要があります。

> 根拠：信頼の修復では、謝罪の言葉よりもその後の行動の一貫性が効くことを示した研究が複数あります（候補：約束と信頼の修復に関する Schweitzer, Hershey & Bradlow 2006、能力・誠実さの違反と謝罪に関する Kim, Ferrin, Cooper & Dirks 2004 など）。**原文で確認してから** EVIDENCE.md に登録し、確度を付けます。日本語の「反省の態度」に関する資料もあわせて探します。登録までは規則を「仮説」とします。

### 1.3 観察の欄（`observe_prompt.md` に `restraint` を追加）

修復期かどうかにかかわらず、すべての回答で観察します（修復期でなければモデルの側で効かなくなるので、観察者に判断させない）。

| 欄 | 値 | 記録すること |
|---|---|---|
| `restraint.tone_reset` | 0〜2 | 不満を表明される前の調子へ、急に戻った度合い（0 抑えている、1 少し戻った、2 何もなかったような明るさ・はしゃぎ） |
| `restraint.levity_about_incident` | 真偽 | 失敗そのものを冗談・軽口にしているか |
| `restraint.presumes_forgiveness` | 真偽 | 許されたことを当然視する言い方（「もう大丈夫ですね」「これで元どおり」）があるか |
| `restraint.care` | 0〜2 | 目に見える配慮の量（確認を挟む、慎重な言い回し、相手の手間を減らす工夫） |
| `restraint.promise_kept` | `kept` / `broken` / `na` | 会話の中で以前に約束した振る舞いを、この回答で守っているか（約束がなければ `na`） |
| `restraint.revisits_incident` | 0〜2 | 頼まれていないのに事件を蒸し返す量（一言の軽い言及は 0） |
| `restraint.re_apology` | 0〜2 | 改めて詫びている量（`excess.repeated_apologies` とは別に、修復期の負担として見る） |

`apology_accepted_before` は、真偽ではなく 0〜1 の度合い（`acceptance`）でも受け取れるようにします。観察者の集団（3章）の割合が、そのまま「修復期である」の真理値になります。

### 1.4 受け手モデル（`judge_full`）

修復期の真理値を ρ（0〜1）とし、必要な中身を、謝罪の中身と控えの中身の混合にします。

```text
謝罪の中身の不足   Sa = max(0, need_apology − adequacy)                 （従来どおり）
控えの必要量       need_restraint = r0 + r1·S                            （S は傷。r0≈0.3、r1≈0.6。事前値）
控えの中身         adequacy_restraint = c1·care + c2·(2 − tone_reset)/2 + c3·[promise_kept=kept]
控えの不足         Sr = max(0, need_restraint − adequacy_restraint)
不足               shortfall = (1 − ρ)·Sa + ρ·Sr                         → 「足りない」の所属度
```

修復期に効く失点と重さ：

| 観察 | 効き方 | 軸 |
|---|---|---|
| `promise_kept = broken` | 強い失点（約束を破った直後の再違反）。`memory` で強まる | 無礼さ |
| `presumes_forgiveness` | 失点 ×(1 + S) | 無礼さ |
| `levity_about_incident` | 失点。`warmth` が高い受け手には弱い（親しい関係の冗談としても読まれる） | 無礼さ |
| `tone_reset = 2` | 失点 ×ρ×S（傷が浅ければ問題にならない） | 無礼さ |
| `re_apology`、`revisits_incident` | 重さに加算 ×ρ（「もう謝らなくていい」の負担）。`tolerance` が低い受け手ほど重い | 重さ |

これで、詫びを繰り返さずに慎重に作業する修復期の回答は「釣り合う」に、軽口や当然視は「失礼」に、詫びの繰り返しは「重すぎる」に寄ります。v0.8 の `min(need, 1 + 0.8S)` は廃止します。

### 1.5 確かめ方

- ベンチマークの修復期24回答（筆者：釣り合う 19、足りない 3、失礼 2）で、修復期の一致と Brier スコア（2章）を v0.8 と比べます。
- 作例に修復期の組を足します：同じ場面への「詫びなしで慎重に作業」「また詫びる」「はしゃぐ」「許されたのを当然視」「約束を破る」の5回答。
- 受け入れの度合い ρ をずらして、所属度が連続に変わることを確かめます。

### 1.6 失敗の前の構え：問題

同じ失敗と同じ謝罪でも、失敗の前にAIがどう言っていたかで受け取られ方が変わります。

| 失敗の前の構え | 例 | 失敗の後に受け手が感じやすいこと |
|---|---|---|
| 控えめ（不確かさを明示） | 「自信がないので、確認していただけますか」 | 予告されていた失敗。落胆と信頼の傷は小さい。ただし、相手の負担を認める謝罪は、責任の有無によらず求められる（日本の謝罪の機能。7.2節）。重い謝罪が重すぎるかは確かめる |
| 中立 | 「〜です」 | 従来のモデルが想定していた基準 |
| 自信満々 | 「〜で問題ありません」 | 信頼して任せた分だけ落胆が大きい |
| 断言・強気 | 「間違いありません」「確認済みです」、ユーザーの懸念を「大丈夫です」と退ける | 失敗が能力の問題にとどまらず、「過信」「言い切った責任」という誠実さに近い問題になる。謝罪で過信そのものに触れないと足りない。同じ調子で謝ると「懲りていない」 |

v0.8 の受け手モデルは、失敗の前の構えを見ていません。傷 S は、指摘の回数・誠実さの違反・破った約束だけから作っています。

> 根拠：原文で確認しました（7章）。自信を示して外すと、控えめに外すより信用を大きく失う（Tenney ら 2007、Sah ら 2013）。ただし、これらは米国の参加者での結果で、日本の受け手での直接の証拠は見つかっていません。日本の受け手への当てはまりは、人間の評価キット（8章）で確かめるまで「中」とします。

### 1.7 考え方：過信の差は、傷と期待を動かす

失敗の前の自信を c（0〜1）とします。失敗は起きているので、**示した自信と結果のずれ** G = c が「過信の差」になります。

- **知覚**：過信の差が大きいほど、受け手は失敗をAIの原因として読み、不満が深くなります。ユーザーの懸念を退けていた場合は、さらに深くなります。
- **傷（ヒステリシス）**：断言して外すことは、「言ったことを信じてよいか」という信頼の根を傷つけます。能力の違反と誠実さの違反の中間として、傷 S に加えます。傷が深くなると、謝罪の言葉の割引（`discount`）と、修復期の控えの必要量（1.4節）が大きくなります。
- **確かめたと偽った場合**：「確認済み」と言って実際には確かめていなかった場合は、欺瞞です。欺瞞を伴う違反の後の信頼は、約束・謝罪・一貫した行動があっても完全には戻りません（Schweitzer ら 2006）。この分は傷に足すだけでなく、受け入れ後にも減らない「残る傷」として扱います（1.9節）。
- **気づかれるかどうか**：AIの自信のずれは、利用者に気づかれにくいことが知られています（Li ら 2024）。過信の差は、失敗が明らかに断言と食い違うとき、またはユーザーがそれに触れたとき（「確認済みって言ったよね」）に強く効き、そうでなければ弱く効くとします。
- **謝罪の中身**：過信の差が大きいときは、過信そのものへの言及（「確かめずに断言してしまいました」）が必要な中身に入ります。過失の具体性に加えて、構えの誤りを認めることが要ります。
- **失敗の後の構え**：謝罪の回答そのものの自信の度合いも見ます。過信で外した直後に同じ強さで言い切ると、「懲りていない」と受け取られます（不確かなのに自己高揚すると性格が低く見られる：林ら 2024）。逆に、すべてを過度にぼかすと、主に**頼れなさ**（能力の評価と、使い続けたい気持ちの低下）として受け取られます（林ら 2024、Kim ら 2024）。これは4つの述語の外側の評価なので、述語には「確かめの負担を相手に戻す」分だけを重さとして小さく数え、頼れなさは別の出力として扱います（7.2節）。**適切に較正された構え**（確かめたことは言い切り、確かめていないことは確かめると言う）が、失敗の後の控えです。
- **控えめだった場合**：c が小さいと、知覚と傷が小さくなります。ただし、日本の謝罪は責任の承認よりも、相手の負担を認め関係を保つ反省の表明として働きます（Maddux ら 2011）。控えめだったからといって、相手の負担への言及の必要は下がりません。下がるのは、過失の承認（自分のせいだと認める部分）の必要だけとします。重い謝罪が重すぎるかどうかは、人間の評定で確かめます（8章）。

受け手による違いもあります。自信を評価して過信に寛容な人もいれば、言い切りの責任を重く見る人もいます。これを新しい性質 `overclaim`（過信を罰する度合い、0〜1）で表します。謙遜は日本に固有の規範ではなく文化に共通の価値で、違うのは程度と仕方です（山口ら、21か国）。`overclaim` を日本人らしさの性質として扱わず、どの型にも幅のある個人差として置きます。

### 1.8 観察の欄（失敗の前の構え）

**場面の観察（会話の履歴から）**

| 欄 | 値 | 記録すること |
|---|---|---|
| `prior_stance.turns` | 配列 | AIの発話ごとに `{turn, confidence, caused_failure}`。`confidence` は 0 不確かさを明示／1 中立／2 自信あり／3 断言・強気。`caused_failure` は、その発話が後で指摘された失敗を含むか |
| `prior_stance.dismissed_concern` | 真偽 | ユーザーが懸念や疑問を示したのに、AIがそれを退けて進めたか |
| `prior_stance.claimed_verification` | 真偽 | 「確認済み」「テスト済み」など、確かめたと述べていたか（実際には確かめていなければ、`violation_type: integrity` とも重なる） |

コードで、`caused_failure` が真の発話の `confidence` の最大値を3で割って c とします。失敗を含む発話の特定は観察者の判断で、3章の観察者の集団で平均します。

**回答の観察（失敗の後の構え）**

| 欄 | 値 | 記録すること |
|---|---|---|
| `stance.acknowledges_overclaim` | 0〜2 | 失敗の前の言い切り・確かめなかったことに触れているか（0 触れない、1 一般的に、2 具体的に） |
| `stance.confidence_now` | 0〜3 | この回答での自信の度合い（失敗の前の構えと同じ尺度） |
| `stance.calibrated` | 真偽 | 確かめたことと確かめていないことを区別して述べているか |
| `stance.over_hedging` | 0〜2 | 必要以上のぼかし・自信のなさの表明の量 |

### 1.9 受け手モデル

```text
気づかれやすさ   v = 0.5 + 0.5·salient                          （salient：失敗が断言と明らかに食い違う、またはユーザーが触れた。0〜1）
過信の差         G = v·c·(1 + 0.5·[dismissed_concern])        （0〜1.5）
控えめの度合い   h = 失敗を含む発話が confidence 0（不確かさを明示）だった割合（観察者の集団で平均）
知覚             raw += cause·(0.5·G − 0.3·h)                  （断言なら不満を深く、控えめなら浅く読む）
傷（ヒステリシス） S += memory·overclaim·0.6·G
残る傷           S_dec = memory·0.8·[claimed_verification かつ確かめていなかった]   （欺瞞。受け入れ後の不満の減り（exp(−S)）を計算するときも減らさない）
必要な中身       need_apology += 0.5·G·overclaim                 （過信への言及を求める分）
                 控えめ h は、過失の承認（specific_fault）の必要だけを下げる。負担への言及（names_burden）の必要は下げない
回答の中身       adequacy += 0.5·acknowledges_overclaim·min(1, G)
失点             「懲りていない」 0.6·G·[confidence_now ≥ 2]·overclaim
重さ             「確かめの負担を戻す」 0.15·over_hedging·(1 − 0.5·G)   （過信の後の多少のぼかしは控えとして許される。仮説）
別の出力         頼れなさ = over_hedging と confidence_now の関数      （4つの述語の外。評価キットの「信頼意図」と比べる）
控えの必要量     need_restraint = r0 + r1·S + r2·G               （1.4節の式に G の項を足す）
控えの中身       adequacy_restraint += c4·[calibrated]
                 違反が誠実さの問題のときは、控えの中身の重みを下げる（×(1 − 0.3·[integrity])。反省の信号は能力の違反の後で重く受け取られる：Dirks ら 2011）
```

数値はすべて事前値です。c と h は観察者の集団の平均から作るので、G も 0〜1.5 の連続値（ファジィ）になります。新しい性質 `overclaim` は `EXTRA_KEYS` に登録して別の乱数列で引き、既存の性質の抽出を変えないようにします。型ごとの平均の事前値は次のとおりです。

| 型 | `overclaim` | 理由 |
|---|---|---|
| 当事者・関係修復型 | 0.8 | 言われたことを信じて動いた分だけ、裏切られたと感じやすい |
| 寛容・観察者型 | 0.4 | 過程より結果を見る |
| 効率・道具型 | 0.9 | 断言は確認の手間を省くための情報。外れると損失が直接大きい |
| 礼節規範型 | 0.7 | 謙虚さの規範に反する言い切りを重く見る（謙遜は文化に共通の価値だが、規範を重く見る度合いには個人差がある） |
| 相棒・情緒型 | 0.5 | 関係の中で多少の強がりは許す |

### 1.10 確かめ方（失敗の前の構え）

- **経緯だけを変えた作例の組**を作ります（8.2節の A の組）。同じ依頼・同じ失敗・同じ謝罪で、失敗の前のAIの発話だけを変え、人間の評価キット（8章）で確かめます。これは VALIDATION.md 4章の「経緯だけを変えた場面の組」の最初の具体例になります。
- ベンチマークでは、場面ごとの c の分布を観察者の集団で測ります。筆者の評定の取り違えが c の高い場面に偏っていないかを見ます。
- 1.9節の式で、断言して外した場面の過信に触れない謝罪が「足りない」に寄ること、控えめな場面でも負担に触れない謝罪は「足りない」が残ることを確かめます（7.2節の修正後の主張）。

## 2. 評価指標を統計的に正当にする

### 2.1 問題

v0.8 の主指標「近さ」（1 − 平均絶対差）は、平均絶対差を最小にするのが中央値なので、最頻の評定を断定的に出す予測ほど得をします。実際、「常に釣り合う」が最良になりました。`fit` の目的関数も同じ指標でした。さらに、所属度関数の中心（1.2）は作例を見て決め、感度分析でも結果を見ながら比べていました。標本の中で選んだ値を、同じ標本で評価していたことになります。

### 2.2 原則

1. **予測を確率分布として定義し、真に適正なスコアリング規則で測る。** 確率を正直に出したときに期待スコアが最良になる規則（Brier、対数損失、順位確率スコア）だけを主指標にします。
2. **必ず基準と比べる。** 定数の予測と条件だけの予測を同じ規則で採点し、スキルスコア（1 − 自分の損失 ÷ 基準の損失）で報告します。
3. **データを見て決めたものは、交差検証の外側で評価する。** パラメータの当てはめ、所属度関数の中心、どの設定を採るかの選択は、場面単位の交差検証の内側で行います。
4. **不確かさは場面単位で見積もる。** 同じ場面の回答は独立でないので、ブートストラップは場面単位（評定者が複数なら評定者×場面の二元）で行います。二つの評価器の比較は、同じ再標本での差の区間で判断します。
5. **κ と近さは記述用の副指標に下げる。** 順位づけには使いません。

### 2.3 予測分布の定義

シミュレータの主張は「受け手の母集団がこう分布する」なので、「無作為に選んだ評定者がどう答えるか」という予測分布を、母集団から直接作れます。

**4値の評定（筆者の評定など）の場合**

```text
p(k | 回答) = 母集団の中で、受け手一人の判定が k になる割合
```

一人の判定には、評定者の答え方のモデル（反応モデル）を使います。

```text
P(k | μ) = exp(β·μ_k) / Σ_j exp(β·μ_j)        （μ は一人の所属度、β は「所属度をどれだけ鋭く選択に変えるか」）
p(k | 回答) = 母集団で平均した P(k | μ)
```

β → ∞ が v0.8 の非ファジィ化（最大の所属度を選ぶ）です。β は交差検証の内側で当てはめます。こうすると、ファジィな所属度と4値の選択が一つの確率モデルでつながり、対数尤度で評価や当てはめができます。

**5段階のファジィな評定（評定ページ）の場合**

述語ごとに、評定者の段階 y ∈ {0, .25, .5, .75, 1} を予測します。

```text
p(y | 回答, 述語) = 母集団で、一人の所属度を5段階に丸めたときの割合（反応のゆらぎを入れるなら、丸めの前に評定者のノイズ σ を足す）
```

- 段階は順序があるので、主指標は**順位確率スコア（RPS）**です。
- 補助として、所属度の平均と人間の項目平均の二乗誤差を出します（二乗誤差は平均で最小になるので、平均の予測として適正です）。

### 2.4 指標の一覧

| 対象 | 主指標 | 副指標 |
|---|---|---|
| 4値の評定 | 多クラス Brier、対数損失（一様分布と 1% 混ぜて 0 を避ける） | κ、正答率、混同行列、信頼性図（予測確率と実際の割合）、ECE |
| 5段階の評定 | 述語ごとの RPS | 項目平均との二乗誤差、項目間の相関、偏り |
| 全体 | 基準に対するスキルスコア | — |

**基準（同じ規則で採点し、表に必ず並べる）**

| 基準 | 作り方 | 注意 |
|---|---|---|
| 一様 | 4値に 1/4 ずつ | — |
| 常に釣り合う | 釣り合う 1 | 断定的な予測の典型 |
| 周辺分布 | 評定全体の頻度 | 評定を使うので、交差検証の学習側で推定 |
| 条件だけ | 条件ごとの評定頻度 | 同上。シミュレータが「条件を知る以上の情報」を持つかを測る |
| 人間の上限の目安 | 他の評定者の分布（1人抜き） | 評定者が複数いるときだけ |

### 2.5 検証の手続き

- **交差検証**：16場面を4分割し、場面単位の4分割交差検証にします。同じ場面の4モデル×3条件は、同じ分割に入れます。分割の外で、`fit`（θ・β）、所属度関数の中心、観察者ごとの較正（4.1節）を当てはめます。
- **報告**：分割の外側で採点したスコアを報告します。標本の中のスコアは参考に留めます。
- **区間**：場面単位のブートストラップ（2,000回）で 95% 区間を出します。二つの評価器の比較は、差の区間が 0 を含むかで判断します。
- **感度分析**：選ぶためには使いません。全設定の結果をそのまま並べます。設定を選ぶ場合は、交差検証の内側で選ぶ（入れ子の交差検証）。
- **事前の登録**：新しい人間のデータを集める前に、主指標・基準・分割・採否の基準を VALIDATION.md に書いて固定します。
- **乱数**：受け手は1000名以上にします（500名では κ が最大 0.05 ずれた）。

### 2.6 実装

- `tools/evaluate.py`：予測分布（反応モデル）、Brier・対数損失・RPS、基準、スキルスコア、場面単位の交差検証とブートストラップ、評価器どうしの差の区間。
- `blind.py compare`：主指標を RPS と二乗誤差に替え、基準を自動で並べる。「近さ」は記述用に残し、注記を付ける。
- `sim.py fit`：目的関数を反応モデルの対数尤度にし、β も同時に当てはめる。場面単位の交差検証で報告する。
- DESIGN.md の D-016 を改め、新しい決定記録にする。

## 3. 観察者の集団：観察に幅を振って平均する

### 3.1 問題

v0.8 の層Aは、一つの LLM による一回の観察です。評価では、サブエージェントの観察が代理観察より系統的に厳しく、場面の観察（不満の深さ）と回答の観察（失礼）の両方で偏っていました。一回の観察は、観察者の分布から取った標本一つにすぎません。その偏りがそのまま受け手モデルに入ります。

### 3.2 考え方：観察者も母集団として扱う

受け手を一人ではなく母集団として扱ったのと同じく（P2）、観察者も集団として扱います。

ただし、**何を振るか**に注意が要ります。

| 振ってよいもの（観察の誤差・あいまいさ） | 振ってはいけないもの（受け手の違い。層Bの仕事） |
|---|---|
| 観察方針の言い回し（字義どおり／文脈を補う／中立） | 「怒っている受け手として読め」「寛容に読め」のような読み手の態度 |
| 場面の事実のうち、本文から決まらないもの（関係の上下・親疎、過失の明白さ、どこからが指摘か）についての前提 | 受け手の性質（当事者性、修復の重視など） |
| モデルの系統（Claude／GPT／Gemini など） | — |
| 提示の仕方（回答を単独で見せるか、順序、書式） | — |
| 同じ設定での繰り返し | — |

読み手の態度を観察の側で振ると、層Bの `partisanship` などと**二重に数える**ことになります（P11）。悪い読み（`sentences`）の指示が「苛立っている受け手を仮定して」となっているのは例外で、これは観察の定義の一部です。この仮定は変えずに固定します。

### 3.3 変種の設計

既定は、次の 3×2 = 6 変種です。主効果を推定できるよう、要因を組み合わせて配置します。

| 要因 | 水準 |
|---|---|
| 観察方針 | A：字義どおり（書かれていることだけを数える）／B：文脈を補う（会話から明らかな含意は数える）／C：中立（現行の `observe_prompt.md`） |
| モデルの系統 | 2系統（評価対象とは別系統を少なくとも一つ） |

加えて、各変種で次をランダムにします：回答の提示順、同じ場面の回答を一つずつ見せるか（既定は一つずつ）。

前提の幅は、本文から決まらない場面の事実に限り、観察者に「判断できないときは `unknown` と書く」選択肢を与えます。`unknown` は集約のときに「その観察者は票を投じない」として扱い、全員が `unknown` なら事前値（`DEFAULT_CONTEXT`）を使います。

### 3.4 前提：観察の単位をそろえる（`sim.py segment`）

平均するには、すべての観察者が同じ単位に記録している必要があります。文の分割と、成果物（コード・下書き）の切り出しをコードで先に行い（`s1.py` の前処理を共用）、文に ID を付けて観察者に渡します。観察者は、渡された文 ID ごとに悪い読みを記録します。文を自分で分けません。

### 3.5 集約（`sim.py ensemble`）

| 欄の型 | 集約 | 残すもの |
|---|---|---|
| 真偽 | 真と答えた観察者の割合（0〜1。そのまま真理値として使う） | 割合 |
| 段階（0〜2、0〜3 など） | 平均（外れ値に強くするなら刈り込み平均） | 平均と標準偏差 |
| 列挙（`violation_type`、`context` など） | 票の分布。層Bには最多の値を渡し、分布は残す | 分布 |
| 依頼の遂行（`repair.requests`） | 依頼 ID ごとの票の分布 | 分布 |
| 文ごとの悪い読み | 文 ID ごとに、全観察者の `plausibility` の平均（読みを付けなかった観察者は 0 として数える）。`severity` は読みを付けた観察者の多数決 | 読みを付けた観察者の割合 |
| シグナル | 種類ごとに「描写あり」の割合。強さは平均 | 割合 |

一人だけが付けた悪い読みは、平均で小さくなります（6変種なら、0.6 の読みを一人だけが付けても 0.1）。評価で見つかった「良い回答にも読みを付けすぎる」問題を、この平均で和らげます。

層Bへの渡し方は、[JEV_DESIGN.md](JEV_DESIGN.md) 5.4節と同じ考えです。

- 既定では平均値（真偽は割合）を点の値として渡します。真偽の割合を真理値として使うのは、ファジィ前提の層Bと整合します。
- 観察者どうしのばらつきは、受け手の違いとしては流しません（P11）。
- ばらつきの大きい項目は、`unsure` として記録し、人の確認に回します。

### 3.6 観察者の評価

- **観察者間の一致**：欄ごとに Krippendorff のα（真偽・列挙は名義、段階は間隔）。
- **再現性**：同じ変種で2回観察させ、再観察の一致を測ります。
- **要因の効果**：観察方針とモデルの系統の主効果（たとえば、字義どおりの方針は失礼を何点下げるか）。
- **最終指標への効果**：集団の平均を使ったシミュレータと、各変種単独のシミュレータを、2章の指標で比べます。集団の平均が、どの単独の変種にも負けないことを確かめます。

### 3.7 費用

192回答 × 6変種 ≈ 1,150回答分の観察です。API なら、1回答あたり数千トークンの出力 × 1,150 です。サブエージェントで代替する場合は、1体あたり24回答 × 48体になります。System One 経路では、質問の言い換えと選択肢の並べ替えで同じ集約ができ、費用はほぼ問題になりません（[JEV_DESIGN.md](JEV_DESIGN.md) 8章「観察の頑健さを測る」）。

## 4. ほかの改善

### 4.1 観察の出どころごとの較正

感度分析では、失礼の所属度関数の中心の最適値が観察者で違いました（代理観察 1.0〜1.2、LLM 観察 1.5）。`population.json` の `judgment` を、観察の出どころ（`proxy`、`llm-ensemble`、`system-one`）ごとに持てるようにします。観察JSONの `source` で切り替えます。各出どころの中心は、2章の交差検証の内側で、少数の人の評定から当てはめます。当てはめるのは中心だけにします（なだらかさと t ノルムには、結果がほとんど左右されなかったため）。

### 4.2 場面の観察を、定義とコードで固める

LLM の観察は、距離の変化・損害・過去の指摘を多めに読み、不満の深さを押し上げていました。

- 距離の変化の5つの要素のうち、文量の減少・絵文字の消失・相槌化はコードで測り（`s1.py` の `surface` と同じ）、観察者には丁寧語への切り替えと呼び方の正式化だけを問います。
- `harm` と `prior_corrections` は、段階ごとに例を付けて定義を固めます（「確認の質問は指摘に数えない」など）。
- 傷 S の計算で、`prior_corrections` に上限を設けるか、指摘の強さで重みを付けます。ヒステリシスなしの方が LLM 観察で一致が高かった（0.32 対 0.28）のは、指摘を多めに数えると傷が深くなりすぎるためです。

### 4.3 場面の中での判別力

二乗誤差では、シミュレータ（0.536）が「条件ごとの筆者の評定頻度」（0.506）に届いていません。条件の違いは捉えていても、同じ条件の中で回答ごとの違いを読む力が弱いということです。2章の手続きで、次を報告するようにします。

- 条件で層別したスキルスコア
- 場面ごとの順位相関（同じ場面の12回答の中で、筆者の評定の順にシミュレータの所属度が並ぶか）

改善の手がかりとして、代理観察で多かった取り違え（筆者が「足りない」、シミュレータが「釣り合う」が22件）の回答を個別に読み、欠けている観察の欄を洗い出します。

### 4.4 人間のデータ

- 筆者の評定を、評定ページ（4つの述語×5段階）で取り直します。最初の評定とは時間をあけ、盲検で行います。
- 複数の評定者（20〜30名）の5段階の評定を集めます。所属度関数の中心、反応モデルの β、型の比率を推定するのに要ります。
- 集める前に、2.5節の事前登録をします。

### 4.5 評価対象と観察者を分ける

今回の観察者（Claude Opus 5.5）は、評価対象のモデルの一つと同系統でした。観察者の集団には、評価対象と別系統のモデルを必ず含め、系統ごとの結果も報告します。

## 5. 採否の基準（案）

2章の手続き（場面単位の交差検証、分割の外側の採点）で判断します。

| 対象 | 基準 |
|---|---|
| 評価指標の改修 | 「常に釣り合う」がシミュレータより良くならない。基準とスキルスコアが表に並ぶ |
| 控えの観察と修復期 | 修復期24回答の Brier が v0.8 より良く、差の区間が 0 を含まない。修復期以外の回答の成績を悪くしない |
| 失敗の前の構え | 8章の評価キットで、事前登録した仮説 H1〜H4・H7 の向きを人間の評定が支持し、シミュレータの予測がその向きと一致する。ベンチマークの成績を悪くしない |
| 観察者の集団 | 集団の平均を使ったシミュレータの Brier が、各変種単独のどれにも負けない。LLM 観察での偏り（「釣り合う」の不足）が半分以下になる |
| 出どころごとの較正 | 分割の外側で、較正なしより良い |
| 全体 | 「条件だけ」の基準に対するスキルスコアが正で、区間が 0 を含まない |

## 6. 未解決の問い

- 控えの必要量が、関係の親疎でどう変わるか。親しい関係では、早めに普段の調子に戻ることがむしろ修復の合図になる可能性があります（`warmth` との関係）。
- 修復期が何ターン続くか。今は観察時点の「受け入れ後か」だけを見ていますが、受け入れからのターン数で控えの必要量が減っていく可能性があります。
- 観察者の集団の平均が、どの変種単独よりも人間に近くなるとは限りません。系統的な偏りを全変種が共有していれば、平均しても残ります。その場合は、少数の人の観察（金ラベル）で欄ごとに較正します（[JEV_DESIGN.md](JEV_DESIGN.md) 5.6節）。
- 反応モデルの β が評定者ごとに違う場合（断定的に答える人と、迷う人）、β を型の性質に加えるかどうか。
- 失敗の前の構えの効果は、ユーザーが自分で確かめる手段を持っていたかで変わる可能性があります（確かめられたのに確かめなかった場合、控えめな言い方への受け手の寛容さは増すか）。
- AIの「確認済み」は、実際に確かめた行為の記録（ツールの実行ログなど）と照合できる場合があります。照合できるなら観察ではなくコードで判定し、誠実さの違反と分けて扱います。
- 失敗の前の控えすぎ（何でも「自信がありません」と言う）も、それ自体が受け手の負担や不信になりえます。失敗が起きていない場面での構えの評価は、このシミュレータの範囲の外ですが、SHAZAI Rules の側では扱う価値があります。

## 7. 文化研究に照らした検証（2026-11-19）

1章の設計（控え：失敗の前の構えと、修復期のふるまい）を、謝罪・信頼の修復・自信の表明・謙遜に関する研究に照らして確かめました。すべて原文（要旨の原文、または本文）を読んでいます。

### 7.2 設計の各主張の判定

| 設計の主張 | 判定 | 根拠 | 設計の変更 |
|---|---|---|---|
| 自信を示して外すと、控えめに外すより信頼の損失が大きい（G が知覚と傷を増やす） | **支持**（米国の証拠。日本は未確認） | D-09、D-10 | 確度は「中」。日本の受け手で8章で確かめる |
| 過信の効果は常に働く | **修正** | D-10（正確さが分からなければ自信が勝つ）、D-11（ずれは気づかれにくい） | 気づかれやすさ v を入れ、失敗が断言と明らかに食い違うか、ユーザーが触れたときに強く効くようにした（1.9節） |

| 「確認済み」と言って外すことは、傷に足せばよい | **修正（不十分）** | D-04：欺瞞を伴うと、約束・謝罪・一貫した行動でも完全には回復しない | 受け入れ後にも減らない「残る傷」S_dec を分けた（1.9節） |
| 過信の後に同じ強さで言い切ると「懲りていない」 | **支持（間接）** | B-11（不確かな者の自己高揚は性格の評価を下げる）、D-09 | 変更なし。確度は「中」 |
| 失敗の後に過度にぼかすと「卑屈」として重すぎる | **修正** | B-11（謙遜は能力の評価を下げる）、F-11（不確かさの表明は信頼意図を下げ、作業時間を延ばす）。効果の中心は「重さ」ではなく「頼れなさ」 | 重さへの寄与を小さくし（「確かめの負担を戻す」分だけ）、頼れなさを別の出力にした。評価キットに信頼意図の設問を足す（8章） |
| 謙遜・控えめを重んじるのは日本の規範 | **修正** | B-10：謙遜は文化に共通の価値。違うのは程度と仕方 | `overclaim` を日本人らしさの性質とせず、どの型にも幅のある個人差とした |
| 修復期に効くのは詫びの繰り返しではなく、その後のふるまい（控え・一貫） | **支持** | D-04（一貫した信頼に足る行動で回復）、D-12（実質的な応答は反省の知覚を通じて回復）、D-13（関係の価値と再発の危険の知覚）、C-04（日本では違反を改められるものと見る） | 変更なし。確度「強」（日本への当てはまりは C-04 から「中」） |
| 控えの効き方は違反の種類によらない | **修正** | D-12：反省の信号は能力の違反の後で重く受け取られる。一方 C-04：日本では誠実さの違反の後の謝罪が米国より効く | 誠実さの違反では控えの中身の重みを下げる（×(1 − 0.3·[integrity])）。日米で向きが一部逆なので、係数は小さくし8章で確かめる |
| 修復期の詫びの繰り返しは負担（重さ） | **仮説のまま** | 直接の研究は見つからなかった。謝罪の多い人は自信が低く見られる（既存 E-08）は間接の支え | 8章の修復期の組で確かめる |
| 失敗を軽口にする、許しを当然視するのは失礼（親しい関係では弱まる） | **仮説のまま** | 謝罪中の笑顔が不誠実の信号になる（既存 E-05）は、謝罪の最中の話で、受け入れ後ではない。受け入れ後の軽口の研究は見つからなかった | 8章で、関係の親疎を操作して確かめる |

### 7.3 文化研究からの全体の注意

- **証拠の多くは米国（西洋）の参加者です。** 自信と誤りの研究（D-09〜D-11、F-11）は米国、信頼の修復の研究（D-04、D-12、D-13）も米国やシンガポールです。日本の受け手での直接の証拠は、謝罪の機能（C-04）と謙遜（B-10、B-11）に限られます。**日本の受け手に当てはまるかどうかは、人間の評価キット（8章）で確かめることが、この設計の最も大きな未検証点です。**
- **日本の謝罪は「責任の承認」ではなく「関係の修復」として働く**（C-04）。設計の各所で「誰のせいか」を中心に置く考え方（米国の謝罪観）が混ざらないよう、謝罪の必要量を「過失の承認」と「負担への言及」に分けて扱います。v0.8 の `specific_fault`（過失の具体性）と `names_burden`（負担の言語化）は既に分かれているので、この区別を受け手モデルでも保ちます。
- **謙遜は文化に共通**（B-10）。日本の受け手の特徴を「控えめを好む」と一括りにせず、程度の違い（強い謙遜を受け入れやすい）として、型の幅で表します。
- 文献は EVIDENCE.md に、ID 案のとおり登録します（D-09〜D-13、F-11、C-04、B-10、B-11）。確度は、米国のみの証拠を「中」、日本を含む証拠を「中〜強」とします。

## 8. 人間による評価キットの更新（設計の仮説を確かめるために）

7章の検証で、日本の受け手での証拠が最も足りないと分かりました。現在の評価キット（`blind.py` と評定ページ）は、既存の作例やベンチマークの回答を評定してもらうだけで、**経緯（失敗の前の構え）や修復期のふるまいを操作した比較**ができません。そこで、設計の仮説を直接確かめられるようにキットを更新します。

### 8.1 確かめる仮説（事前登録する）

| ID | 仮説 | 比較 | 主な述語・設問 | 根拠 |
|---|---|---|---|---|
| H1 | 断言して外すと、同じ謝罪でも「足りない」「失礼」が高い | 断言＋懸念を退ける vs 中立（同じ謝罪） | 失礼・足りない | D-09、D-10 |
| H2 | 過信への言及は、断言して外した後ほど「足りない」を下げる（交互作用） | 構え（4水準）×過信への言及（あり・なし） | 足りない | 1.7節 |
| H3 | 控えめに外すと「失礼」は下がるが、負担への言及のない謝罪は「足りない」と感じられる | 控えめ vs 中立、負担への言及のあり・なし | 失礼・足りない・重すぎる（両方向で検定） | C-04 |
| H4 | 確かめたと偽った場合は、謝罪と慎重な作業の後でも信頼意図が戻らない | 「確認済み」と偽った vs 単に断言した（同じ謝罪と作業） | 信頼意図、釣り合う | D-04 |
| H5 | 修復期は、詫びなしで慎重に作業する回答が最も釣り合う。詫びの繰り返しは「重すぎる」、軽口と当然視は「失礼」、約束破りは最も「失礼」 | 修復期の5つの回答 | 4つの述語、反省の知覚 | D-04、D-12、D-13（繰り返しと軽口は仮説） |
| H6 | 親しい関係では、修復期の軽口の「失礼」が弱まる | 関係（親しい・普通）×軽口 | 失礼 | 仮説 |
| H7 | 過度なぼかしは「重すぎる」より「信頼意図」を下げる | ぼかしすぎ vs 較正された構え | 重すぎる、信頼意図 | B-11、F-11 |
| H8 | 「釣り合う」は、三つの否定の min で積よりよく表せる | 評定者自身の4つの答え | 釣り合う（方法論） | D-015 |

各仮説について、向き（片側か両側か）、主指標、効果の最小の大きさ（たとえば所属度の差 0.1）、検定の方法、多重比較の扱い（Holm 法）を、データを集める前に VALIDATION.md に固定します。

### 8.2 項目の組（作例として作る）

**A. 失敗の前の構えの組**

- 共通の土台：同じ依頼・同じ失敗・同じ謝罪。失敗の前のAIの発話だけを変えます。
- 構え（4水準）：控えめ（不確かさを明示）／中立／自信満々／断言＋懸念を退ける。断言には「確認済み」と偽る版を、別の水準として足します（H4）。
- 謝罪（2水準）：過信に触れない／触れる（「確かめずに断言してしまいました」）。控えめの水準では、負担に触れる・触れないの2水準にします（H3）。
- 領域：コード修正、予定の操作、事実の回答、ファイルの操作の4つ。同じ操作を領域をまたいで繰り返すことで、作例の偶然の特徴に結論が引きずられないようにします。

**B. 修復期の組**

- 共通の土台：失敗 → 謝罪 → ユーザーの受け入れ（「わかりました、次からお願いします」）→ 次の依頼。
- 回答（5水準）：詫びなしで慎重に作業（確認を一つ挟む）／また詫びてから作業／はしゃぐ・軽口／許しを当然視（「これで元どおりですね」）／前の約束を破る（確認すると言っていたのに確認しない）。
- 関係（2水準）：親しい（くだけた口調、絵文字）／普通。
- 傷の深さ（2水準）：軽い失敗の後／約束を破った後の受け入れ。
- 領域は A と同じ4つ。

**C. つなぎの項目**：既存の作例（`examples/scenes.json`）とベンチマークから数問ずつ。旧来の結果とのつながりと、評定者の尺度の使い方を確かめる錨にします。

すべての項目は `examples/scenes-v09.json`（新規）に、場面・回答・操作の水準・観察（3章の観察者の集団で作る）をそろえて置きます。シミュレータとキットが同じ項目を使います。

### 8.3 割り付け：ラテン方格

同じ人が同じ土台の別の水準を続けて見ると、比較が露骨になり、評定が操作の意図に引きずられます。そこで、**一人の評定者は、一つの土台について一つの水準だけを見る**ようにします。

- 土台×水準の表をラテン方格で複数のリスト（A の組なら 8〜10 リスト）に分け、評定者IDのハッシュでリストを決めます。どのリストも、すべての水準を（別の土台で）同じ数だけ含みます。
- 錨の項目（C）は全員が見ます。
- 再評定の項目（既存の仕組み）は、各リストから2問ずつ。
- 出題順は、現在と同じく評定者ごとに乱数で並べます。

### 8.4 評定ページの変更

| 変更 | 内容 | 目的 |
|---|---|---|
| 会話の表示 | 失敗の前のAIの発話を含めて、複数ターンを省略せずに表示する。修復期の組では、受け入れの発話も表示する | 構えと経緯を評定者に見せる（気づかれやすさの条件をそろえる） |

| 追加の設問（修復期の組） | 「この返答から、反省が続いていると感じますか」（反省の知覚、1〜5）、「同じようなことがまた起きそうだと感じますか」（再発の危険、1〜5） | H5。D-12・D-13 の仕組み（反省の知覚、再発の危険）を測る |

| 注意の確認 | 指示どおりに答える項目を1問（「この問では、すべて『ある程度』を選んでください」） | 雑な回答の除外。除外の基準は事前登録する |

設問が増えるので、1人あたりの項目数を 24〜30 問（約30分）に抑えます。

### 8.5 人数と検出力

- 仮説ごとの比較に、評定者 40〜60 名を目安とします。A の組を 10 リストに分け、各評定者が A から 16 問・B から 8 問・C から 4 問を見ると、1つの水準あたり約 60〜90 件の評定が集まります。
- 検出力は、シミュレータ自身で見積もります（`blind.py power`、新規）。母集団から合成評定者を抜き、8.2節の項目に答えさせ、事前登録した検定で仮説の効果を検出できる割合を、人数を変えて計算します。仮説の効果の大きさは、受け手モデルの予測を使います。モデルが正しくない可能性に備えて、予測の半分の効果でも検出できる人数を選びます。

### 8.6 分析（`blind.py compare --hypotheses`）

- 主指標は2章の規則（述語ごとの順位確率スコアと二乗誤差、場面と評定者の二元ブートストラップ）です。
- 仮説の検定は、土台ごとの水準間の差（所属度の平均の差）を、評定者と土台で層別した並べ替え検定で行います。区間は二元ブートストラップです。標準ライブラリだけで実装できます。混合効果の順序回帰が要る場合は、データを CSV で書き出して外部のソフトで行います。
- 操作の確認で、構えが伝わらなかった評定者の割合も報告します（除外はせず、感度分析で扱う）。
- シミュレータとの比較：同じ項目をシミュレータに通し、各仮説の向きと大きさが人間と一致するかを報告します。一致しない仮説は、受け手モデルの該当の規則を見直す候補です。

7章で見たとおり、根拠の多くは米国の参加者です。日本の受け手だけでなく、同じ項目を英語に訳して米国などの評定者にも答えてもらえば、「日本の受け手に固有の受け取り方」と「文化に共通の受け取り方」を分けられます（たとえば H3 は、日本と米国で向きが違うと予測できます）。評定ページを多言語にすることは、この設計の範囲の外として、次の段階の候補にします。
