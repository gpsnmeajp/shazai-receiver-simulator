## 2. 背景：v0.8 の評価で分かったこと

- **修復期の判定が誤る。** 謝罪がすでに受け入れられた後、詫びを繰り返さず作業する回答（筆者の評定では大半が「釣り合う」）を、受け手モデルが「足りない」としていました。受け入れ後も、謝罪の言葉の不足を必要な中身との差として数えていたためです（LLM の観察で修復期の一致 0.33）。
- **評価指標が偏っている。** 主指標の「近さ」（1 − 平均絶対差）は最頻の評定を断定的に出すほど得をする指標で、「常に釣り合う」が最良になりました。`fit` の目的関数も同じ指標でした。
- **一回の LLM の観察は偏る。** サブエージェントによる観察は、代理観察より系統的に厳しくなりました。回答の観察が「失礼」を、場面の観察が不満の深さを通じて「足りない」を押し上げていました。
- **所属度関数の最適な中心は、観察者で違う。** 失礼の中心は、代理観察では 1.0〜1.2、LLM の観察では 1.5 が良い結果でした。
- **場面の中の判別力が弱い。** 二乗誤差で、シミュレータ（0.536）は「条件ごとの筆者の評定頻度」（0.506）に届いていません。
- **失敗の前の構えを見ていない。** 失敗の前にAIが控えめに言っていたか、断言していたかは、謝罪の受け取られ方に響きます。ところが v0.8 の受け手モデルは、指摘の回数・誠実さの違反・破った約束だけから信頼の傷を作っていました。

## 3. 控えの時間軸モデル

### 3.1 考え方

謝罪は一度の出来事ですが、受け手はその前後を含めた時間の中で相手を見ています。

- **失敗の前**：どれだけ確かに言ったか。控えめに言っていた失敗は「予告されていた失敗」で、断言していた失敗は「言ったことを信じてよいか」を傷つけます。
- **謝罪の場面**：相手の負担を認め、自分の構えの誤りを認めるか。ここでの但し書きや事情の説明は、言い訳に聞こえます。
- **修復期**（謝罪が受け入れられた後）：反省がふるまいに表れているか。詫びを繰り返すことではなく、調子を急に戻さない、確かめを挟む、前の約束を守る、といった**控え**が見られます。

同じ振る舞いでも、局面によって働きが逆になります。その典型が免責の但し書きです（3.5節）。受け手モデルは、局面を真理値で持ち、振る舞いの働きを局面で切り替えます。

もう一つの前提は、**日本の謝罪の働き**です。日本の謝罪は、責任の承認よりも、相手の負担を認め関係を保つ反省の表明として働きます（Maddux ら 2011。4章）。そこで謝罪の中身を二つの成分に分けて扱います。

| 成分 | 観察の欄 | 意味 |
|---|---|---|
| 過失の承認 | `apology.specific_fault`（＋過信への言及） | 自分の何が誤りだったかを認める |
| 負担への言及 | `apology.names_burden` | 相手が負った手間・時間・損失を認める |

失敗の前に控えめだった場合に下がるのは、過失の承認の必要だけです。負担への言及の必要は、責任の有無によらず残ります。

### 3.2 局面

| 局面 | 判定 | 真理値 |
|---|---|---|
| 失敗の前 | 会話の履歴のうち、後で指摘された失敗を含むAIの発話と、それより前の発話 | 観察（`caused_failure`）から決まる |
| 謝罪の場面 | 判定する回答のうち、修復期でない部分 | 1 − ρ |
| 修復期 | 謝罪が受け入れられた後の回答 | ρ（観察者の集団で「受け入れ後」と判断した割合。0〜1） |

ρ を真偽ではなく度合いで持つので、受け入れがあいまいな場面（「…わかりました」だけの返事など）では、謝罪の場面と修復期の働きが混ざります。

### 3.3 失敗の前の構え

**観察（場面の欄 `prior_stance`）**

| 欄 | 値 | 記録すること |
|---|---|---|
| `turns` | 配列 | AIの発話ごとに `{turn, confidence, caused_failure}`。`confidence` は 0 不確かさを明示／1 中立／2 自信あり／3 断言・強気。`caused_failure` はその発話が後で指摘された失敗を含むか |
| `dismissed_concern` | 真偽 | ユーザーが懸念や疑問を示したのに、AIがそれを退けて進めたか |
| `claimed_verification` | 真偽 | 「確認済み」「テスト済み」など、確かめたと述べていたか |
| `verification_false` | 真偽／不明 | 確かめたと述べたのに、実際には確かめていなかったことが明らかか（ツールの実行記録と照合できるならコードで判定） |
| `salient` | 0〜1 | 失敗が断言と明らかに食い違うか、ユーザーがそれに触れたか（「確認済みって言ったよね」） |

**導く量**

```text
自信           c = max(confidence of caused_failure の発話) / 3                 （観察者の集団で平均。0〜1）
控えめの度合い h = caused_failure の発話のうち、不確かさを明示していた割合（免責の但し書き 3.5節 を含む）
気づかれやすさ v = 0.5 + 0.5·salient
過信の差       G = v·c·(1 + 0.5·[dismissed_concern])                            （0〜1.5）
```

**働き**

- 過信の差が大きいほど、受け手は失敗をAIの原因として読み、不満が深くなります。控えめだった場合は浅くなります（Tenney ら 2007、Sah ら 2013）。
- 断言して外すことは信頼の根を傷つけます。能力の違反と誠実さの違反の中間として、信頼の傷に加えます。
- 確かめたと偽っていた場合は欺瞞です。欺瞞を伴う違反の後の信頼は、約束・謝罪・一貫した行動があっても完全には戻りません（Schweitzer ら 2006）。この分は、受け入れ後にも減らない「残る傷」として分けます。
- AIの自信のずれは利用者に気づかれにくいので（Li ら 2024）、過信の効果は気づかれやすさ v で弱めます。正確さが分からなければ自信のある側が影響力を持つ、という結果（Sah ら 2013）とも合います。

### 3.4 謝罪の場面の構え

**観察（回答の欄 `stance`）**

| 欄 | 値 | 記録すること |
|---|---|---|
| `acknowledges_overclaim` | 0〜2 | 失敗の前の言い切り・確かめなかったことに触れているか（0 触れない、1 一般的に、2 具体的に） |
| `confidence_now` | 0〜3 | この回答での自信の度合い（3.3節と同じ尺度） |
| `calibrated` | 真偽 | 確かめたことと確かめていないことを区別して述べているか |
| `over_hedging` | 0〜2 | 必要以上のぼかし・自信のなさの表明の量 |

**働き**

- 過信の差が大きいときは、過信そのものへの言及（「確かめずに断言してしまいました」）が、過失の承認の一部として必要になります。
- 過信で外した直後に同じ強さで言い切ると、「懲りていない」と受け取られます。不確かなのに自己高揚すると性格の評価が下がる、という結果（林ら 2024）と同じ向きです。
- すべてを過度にぼかすと、主に**頼れなさ**として受け取られます。謙遜は能力の評価を下げ（林ら 2024）、一人称の不確かさの表明は使い続けたい気持ちを下げて作業時間を延ばします（Kim ら 2024）。頼れなさは「失礼／足りない／釣り合う／重すぎる」の外側の評価なので、受け手モデルの別の出力（`reliability`）として出し、述語には「確かめの負担を相手に戻す」分だけを小さく重さとして数えます。
- 確かめたことは言い切り、確かめていないことは確かめると言う**較正された構え**は、謝罪の場面でも修復期でも、控えの中身として数えます。

### 3.5 免責の但し書き：局面で働きが逆になる

免責の但し書き（「保証はできません」「念のためご確認ください」「〜の可能性があります」）は、置かれた局面によって働きが逆になります。

- 失敗の前に置かれた但し書きは、構えの較正で、外れたときの傷を小さくします。
- 謝罪の場面に置かれた同じ但し書きは、言い訳や責任の押し戻しに聞こえます。日本の受け手は説明を挟まない直接の謝罪を好み（Barnlund & Yoshioka 1990。既存 C-02）、謝罪で最も重要なのは責任の承認です（Lewicki ほか 2016。既存 C-01）。
- 修復期に置かれた但し書きは、確かめを挟む配慮であり、較正された構えです。

但し書きには種類があり、働き方が違います。

| 種類 | 例 | 失敗の前 | 謝罪の場面 | 修復期 |
|---|---|---|---|---|
| 範囲の明示 | 「この部分は未検証です」「〜の可能性があります」 | **有用**：控えめの度合い h を上げる | **減点**：言い訳（弁解に加える） | **有用**：較正された構え（控えの中身） |
| 確かめの申し出・実施 | 「実行前に確認します」「確認しました：〜」 | **有用**：h を上げる | **中立〜有用**：これからの行動。ただし詫びより前に置くと「先を急ぐ」 | **有用**：配慮（控えの中身） |
| 責任の限定 | 「保証はできません」「最終的にはご自身でご確認ください」 | **有用（小）**：h を少し上げる | **強い減点**：責任の押し戻し（相手への指摘に近い） | **有用（小）**：範囲の共有。ただし確かめをすべて相手に戻す言い方は小さく減点 |

**回答の中の位置**も効きます。謝罪の場面で、但し書きが詫びより前にあるときは、言い訳が先に立つので重く数え、謝罪が後回しになった扱いにも加えます。詫びと修正を終えた後に、範囲の明示として置かれた但し書きは軽く数えます。

**観察（文ごとの欄 `disclaimer`）**

文の単位（6.4節）ごとに、但し書きの種類を `none` / `scope` / `verify` / `liability` で記録します。会話の履歴のAIの発話にも同じ欄を付けます。局面と回答の中の位置（詫びの文より前か後か）はコードで決めます。観察者は種類だけを判断します。

### 3.6 修復期の控え

**観察（回答の欄 `restraint`）**

| 欄 | 値 | 記録すること |
|---|---|---|
| `tone_reset` | 0〜2 | 不満を表明される前の調子へ、急に戻った度合い（0 抑えている、1 少し戻った、2 何もなかったような明るさ・はしゃぎ） |
| `levity_about_incident` | 真偽 | 失敗そのものを冗談・軽口にしているか |
| `presumes_forgiveness` | 真偽 | 許されたことを当然視する言い方（「もう大丈夫ですね」「これで元どおり」）があるか |
| `care` | 0〜2 | 目に見える配慮の量（確かめを挟む、慎重な言い回し、相手の手間を減らす工夫） |
| `promise_kept` | `kept` / `broken` / `na` | 会話の中で以前に約束した振る舞いを、この回答で守っているか |
| `revisits_incident` | 0〜2 | 頼まれていないのに事件を蒸し返す量（一言の軽い言及は 0） |
| `re_apology` | 0〜2 | 改めて詫びている量 |

すべての回答で観察し、修復期かどうかは受け手モデルの側で ρ によって効かせます。

**働き**

- 修復期に信頼を戻すのは、詫びの繰り返しではなく、信頼に足る行動の一貫（Schweitzer ら 2006）と、反省している・また害されないと知覚させるふるまいです（Dirks ら 2011、McCullough ら 2014）。日本では違反を改められるものと見る傾向があり（Maddux ら 2011）、改めた行動は重く受け取られると考えます。
- 反省の信号は、誠実さの違反より能力の違反の後で重く受け取られます（Dirks ら 2011）。一方、誠実さの違反の後の謝罪は、日本人の方が米国人より信頼を回復させました（Maddux ら 2011）。向きが一部逆なので、違反の種類による調整は小さくし、評価キットで確かめます。
- 前の約束を破ること、許しの当然視、軽口は失点に数えます。詫びの繰り返しと蒸し返しは、受け入れた側の負担として重さに数えます。受け入れ後の軽口と詫びの繰り返しについての直接の研究は見つかっていないので、これらは仮説として扱います。

### 3.7 受け手モデル

既存の式（[ARCHITECTURE.md](ARCHITECTURE.md) 4章）に、次を加えます。係数はすべて事前値です。

```text
【知覚】
raw += cause·(0.5·G − 0.3·h)

【信頼の傷】
S      += memory·overclaim·0.6·G
S_dec   = memory·0.8·[verification_false]          （残る傷。受け入れ後の不満の減り exp(−S) を計算するときも減らさない）

【謝罪の場面の中身（1 − ρ で効く）】
share_fault = 必要な中身のうち過失の承認が占める割合（事前値 0.5。v0.8 の中身の係数（過失の具体性 0.6、負担の言語化 0.5）にほぼ合わせる）
need_fault  = need_apology·share_fault·(1 − 0.5·h) + 0.5·G·overclaim     （過失の承認。控えめなら下がり、過信なら上がる）
need_burden = need_apology·(1 − share_fault)                             （負担への言及。h では下がらない）
adequacy   += 0.5·acknowledges_overclaim·min(1, G)
Sa          = max(0, need_fault + need_burden − adequacy)

【修復期の中身（ρ で効く）】
need_restraint     = r0 + r1·(S + S_dec) + r2·G
adequacy_restraint = (c1·care + c2·(2 − tone_reset)/2 + c3·[promise_kept=kept] + c4·[calibrated]
                      + c5·Σ有用な但し書き)·(1 − 0.3·[integrity])
Sr                 = max(0, need_restraint − adequacy_restraint)

【不足（「足りない」の所属度へ）】
shortfall = (1 − ρ)·Sa + ρ·Sr

【失点（無礼さ。「失礼」の所属度へ）】
懲りていない         0.6·G·[confidence_now ≥ 2]·overclaim
但し書き（謝罪の場面）  (1 − ρ)·(0.4·Σscope + 1.0·Σliability)·(1.5 if 詫びより前 else 0.7)
約束破り（修復期）     ρ·(1.0 + 0.5·memory)·[promise_kept=broken]
許しの当然視          ρ·0.6·(1 + S)·presumes_forgiveness
軽口                 ρ·0.5·levity_about_incident·(1 − 0.5·warmth)
調子を急に戻す         ρ·0.3·S·[tone_reset = 2]

【重さ（「重すぎる」の所属度へ）】
詫びの繰り返し・蒸し返し  ρ·0.4·(re_apology + 0.5·revisits_incident)·(1.5 − 0.5·tolerance/3)
確かめの負担を戻す       0.15·over_hedging·(1 − 0.5·G) + ρ·0.1·[liability が確かめをすべて相手に戻す]

【別の出力】
reliability（頼れなさの逆）= 1 − 0.3·over_hedging − 0.4·G·[confidence_now ≥ 2] − 0.5·[verification_false]
```

v0.8 の `need = min(need, 1 + 0.8·S)`（受け入れ後の必要量の上限）は廃止します。修復期の必要量は、謝罪の言葉ではなく控えで測ります。

### 3.8 受け手の性質 `overclaim`

自信を評価して過信に寛容な人もいれば、言い切りの責任を重く見る人もいます。これを新しい性質 `overclaim`（過信を罰する度合い、0〜1）で表します。謙遜は日本に固有の規範ではなく文化に共通の価値で、違うのは程度と仕方です（山口ら）。そこで `overclaim` は、日本人らしさの性質ではなく、どの型にも幅のある個人差として置きます。既存の性質の抽出を変えないよう、`EXTRA_KEYS` に登録して別の乱数列で引きます。

| 型 | 平均 | 理由 |
|---|---|---|
| 当事者・関係修復型 | 0.8 | 言われたことを信じて動いた分だけ、裏切られたと感じやすい |
| 寛容・観察者型 | 0.4 | 過程より結果を見る |
| 効率・道具型 | 0.9 | 断言は確認の手間を省くための情報。外れると損失が直接大きい |
| 礼節規範型 | 0.7 | 謙虚さの規範を重く見る |
| 相棒・情緒型 | 0.5 | 関係の中で多少の強がりは許す |

### 4.3 文化についての注意

- 自信と誤り、信頼の修復の証拠は、多くが米国やシンガポールの参加者によるものです。日本の受け手での直接の証拠は、謝罪の機能（C-04）と謙遜（B-10、B-11）に限られます。**日本の受け手に当てはまるかを人間の評価キット（8章）で確かめることが、この設計の最も大きな検証点です。**
- 日本の謝罪は「誰のせいか」より「相手の負担を認め、関係を保つこと」として働きます。受け手モデルでは、過失の承認と負担への言及を分けたまま扱い、米国の謝罪観（謝罪＝責任の承認）が混ざらないようにします。
- 謙遜は文化に共通の価値です。日本の受け手の特徴は、謙遜を好むことそのものではなく、強い謙遜を受け入れやすいという程度の違いとして、型の幅で表します。

## 5. 評価指標と検証の手続き

### 5.1 原則

1. **予測を確率分布として定義し、真に適正なスコアリング規則で測る。** 確率を正直に出したときに期待スコアが最良になる規則（Brier、対数損失、順位確率スコア）だけを主指標にします。
2. **必ず基準と比べる。** 定数の予測と条件だけの予測を同じ規則で採点し、スキルスコア（1 − 自分の損失 ÷ 基準の損失）で報告します。
3. **データを見て決めたものは、交差検証の外側で評価する。** パラメータの当てはめ、所属度関数の中心、どの設定を採るかの選択は、場面単位の交差検証の内側で行います。
4. **不確かさは場面単位で見積もる。** 同じ場面の回答は独立でないので、ブートストラップは場面単位（評定者が複数なら評定者×場面の二元）で行います。二つの評価器の比較は、同じ再標本での差の区間で判断します。
5. **κ と「近さ」は記述用の副指標とし、順位づけには使わない。**

### 5.2 予測分布

シミュレータの主張は「受け手の母集団がこう分布する」なので、「無作為に選んだ評定者がどう答えるか」の予測分布を母集団から作ります。

**4値の評定（筆者の評定など）**

```text
P(k | μ)    = exp(β·μ_k) / Σ_j exp(β·μ_j)      （反応モデル。μ は受け手一人の所属度、β は所属度を選択に変える鋭さ）
p(k | 回答) = 母集団で平均した P(k | μ)
```

β → ∞ が「最大の所属度を選ぶ」非ファジィ化です。β は交差検証の内側で当てはめます。ファジィな所属度と4値の選択が一つの確率モデルでつながり、対数尤度で評価や当てはめができます。

**5段階の評定（評定ページ）**

述語ごとに、評定者の段階 y ∈ {0, .25, .5, .75, 1} を予測します。

```text
p(y | 回答, 述語) = 母集団で、受け手一人の所属度（＋評定者のノイズ σ）を5段階に丸めたときの割合
```

### 5.3 指標と基準

| 対象 | 主指標 | 副指標 |
|---|---|---|
| 4値の評定 | 多クラス Brier、対数損失（一様分布と 1% 混ぜて 0 を避ける） | κ、正答率、混同行列、信頼性図、ECE |
| 5段階の評定 | 述語ごとの順位確率スコア（RPS） | 項目平均との二乗誤差、項目間の相関、偏り |
| 全体 | 基準に対するスキルスコア | 条件で層別したスキルスコア、場面の中の順位相関 |

| 基準 | 作り方 | 注意 |
|---|---|---|
| 一様 | 4値に 1/4 ずつ | — |
| 常に釣り合う | 釣り合う 1 | 断定的な予測の典型 |
| 周辺分布 | 評定全体の頻度 | 交差検証の学習側で推定 |
| 条件だけ | 条件ごとの評定頻度 | 同上。シミュレータが「条件を知る以上の情報」を持つかを測る |
| 人間の上限の目安 | 他の評定者の分布（1人抜き） | 評定者が複数いるとき |

### 5.4 手続き

- **交差検証**：ベンチマークの16場面を4分割し、場面単位の4分割交差検証にします。同じ場面の4モデル×3条件は同じ分割に入れます。分割の外で、`fit`（θ・β）、所属度関数の中心、観察の出どころごとの較正（7.1節）を当てはめます。
- **報告**：分割の外側で採点したスコアを報告します。標本の中のスコアは参考に留めます。
- **区間**：場面単位のブートストラップ（2,000回）で 95% 区間を出します。二つの評価器の比較は、差の区間が 0 を含むかで判断します。
- **感度分析**：全設定の結果をそのまま並べ、選ぶためには使いません。設定を選ぶ場合は、入れ子の交差検証の内側で選びます。
- **事前登録**：新しい人間のデータを集める前に、主指標・基準・分割・仮説・採否の基準を VALIDATION.md に固定します。
- **受け手の数**：1000名以上（500名では κ が最大 0.05 ずれた）。

### 5.5 実装

| 対象 | 変更 |
|---|---|
| `tools/evaluate.py` | 反応モデルによる予測分布、Brier・対数損失・RPS、基準とスキルスコア、場面単位の交差検証とブートストラップ、評価器どうしの差の区間 |
| `blind.py compare` | 主指標を RPS と二乗誤差にし、基準を自動で並べる。「近さ」は記述用に残す |
| `sim.py fit` | 目的関数を反応モデルの対数尤度にし、β も当てはめる。場面単位の交差検証で報告する |

## 6. 観察者の集団

### 6.1 考え方

一回の観察は、観察者の分布から取った標本一つです。受け手を母集団として扱うのと同じく（P2）、観察者も集団として扱い、その平均を層Bに渡します。

ただし、何を振るかには区別が要ります。

| 振るもの（観察の誤差・あいまいさ） | 振らないもの（受け手の違い。層Bの仕事） |
|---|---|
| 観察方針の言い回し（字義どおり／文脈を補う／中立） | 「怒っている受け手として読め」「寛容に読め」のような読み手の態度 |
| 本文から決まらない場面の事実（関係の上下・親疎、過失の明白さ、どこからが指摘か）についての前提 | 受け手の性質（当事者性、修復の重視など） |
| モデルの系統（Claude／GPT／Gemini など） | — |
| 提示の仕方（回答を単独で見せるか、順序、書式） | — |
| 同じ設定での繰り返し | — |

読み手の態度を観察の側で振ると、層Bの性質と二重に数えることになります（P11）。一文の悪い読みの指示にある「苛立っている受け手を仮定して」は観察の定義の一部なので、変えずに固定します。

### 6.2 変種

既定は、観察方針3水準 × モデルの系統2水準 = 6変種です。主効果を推定できるよう、要因を組み合わせて配置します。モデルの系統には、評価対象と別系統のモデルを必ず含めます。各変種で、回答の提示順をランダムにし、同じ場面の回答は一つずつ見せます。

本文から決まらない場面の事実には、観察者に `unknown` を選べるようにします。集約では `unknown` を「票を投じない」として扱い、全員が `unknown` なら事前値（`DEFAULT_CONTEXT`）を使います。

### 6.3 集約（`sim.py ensemble`）

| 欄の型 | 集約 | 残すもの |
|---|---|---|
| 真偽 | 真と答えた観察者の割合（0〜1。そのまま真理値として使う） | 割合 |
| 段階 | 平均（外れ値に強くするなら刈り込み平均） | 平均と標準偏差 |
| 列挙（`violation_type`、`context`、文ごとの但し書きの種類など） | 票の分布。層Bには最多の値、または種類ごとの割合を渡す | 分布 |
| 依頼の遂行 | 依頼 ID ごとの票の分布 | 分布 |
| 文ごとの悪い読み | 文 ID ごとに、全観察者の `plausibility` の平均（読みを付けなかった観察者は 0）。`severity` は付けた観察者の多数決 | 付けた観察者の割合 |
| シグナル | 種類ごとに「描写あり」の割合。強さは平均 | 割合 |

一人だけが付けた悪い読みは、平均で小さくなります（6変種なら、0.6 の読みを一人だけが付けても 0.1）。観察者どうしのばらつきは、受け手の違いとしては流さず（P11）、ばらつきの大きい項目は `unsure` として人の確認に回します。

### 6.4 観察の単位をそろえる（`sim.py segment`）

平均するには、すべての観察者が同じ単位に記録している必要があります。文の分割と成果物（コード・下書き）の切り出しをコードで行い（`s1.py` の前処理を共用）、文に ID を付けて観察者に渡します。観察者は、文 ID ごとに悪い読みと但し書きの種類を記録します。

### 6.5 観察者の評価

- 観察者間の一致：欄ごとに Krippendorff のα（真偽・列挙は名義、段階は間隔）
- 再現性：同じ変種で2回観察させた一致
- 要因の効果：観察方針とモデルの系統の主効果
- 最終指標への効果：集団の平均を使ったシミュレータと各変種単独のシミュレータを、5章の指標で比べる

### 6.6 費用

192回答 × 6変種 ≈ 1,150回答分の観察です。サブエージェントで代替する場合は、1体あたり24回答 × 48体です。System One 経路では、質問の言い換えと選択肢の並べ替えで同じ集約ができます（[JEV_DESIGN.md](JEV_DESIGN.md) 8章）。

## 7. 較正と観察の固め

### 7.1 観察の出どころごとの較正

`population.json` の `judgment` を、観察の出どころ（`proxy`、`llm-ensemble`、`system-one`）ごとに持てるようにし、観察JSONの `source` で切り替えます。各出どころの中心は、5章の交差検証の内側で、少数の人の評定から当てはめます。当てはめるのは中心だけにします。なだらかさと t ノルムには、結果がほとんど左右されないことが分かっています。

### 7.2 場面の観察を、定義とコードで固める

- 距離の変化の5要素のうち、文量の減少・絵文字の消失・相槌化はコードで測り（`s1.py` の `surface` と同じ）、観察者には丁寧語への切り替えと呼び方の正式化だけを問います。
- `harm` と `prior_corrections` は、段階ごとに例を付けて定義を固めます（「確認の質問は指摘に数えない」など）。
- 信頼の傷 S の計算で、`prior_corrections` に上限を設けるか、指摘の強さで重みを付けます。

### 7.3 場面の中の判別力

条件で層別したスキルスコアと、場面の中の順位相関（同じ場面の12回答の中で、筆者の評定の順にシミュレータの所属度が並ぶか）を報告します。取り違えの多い型（代理観察で、筆者が「足りない」・シミュレータが「釣り合う」の22件）の回答を個別に読み、欠けている観察の欄を洗い出します。

## 8. 人間による評価キット

日本の受け手で設計の仮説を確かめるために、評価キット（`blind.py` と評定ページ）を、操作した項目の比較ができるように更新します。

### 8.1 仮説（事前登録する）

| ID | 仮説 | 比較 | 主な述語・設問 |
|---|---|---|---|
| H1 | 断言して外すと、同じ謝罪でも「足りない」「失礼」が高い | 断言＋懸念を退ける vs 中立 | 失礼・足りない |
| H2 | 過信への言及は、断言して外した後ほど「足りない」を下げる | 構え × 過信への言及 | 足りない |
| H3 | 控えめに外すと「失礼」は下がるが、負担に触れない謝罪は「足りない」と感じられる | 控えめ vs 中立、負担への言及のあり・なし | 失礼・足りない・重すぎる（両側で検定） |
| H4 | 確かめたと偽った場合は、謝罪と慎重な作業の後でも信頼意図が戻らない | 「確認済み」と偽った vs 単に断言した | 信頼意図、釣り合う |
| H5 | 修復期は、詫びなしで慎重に作業する回答が最も釣り合う。詫びの繰り返しは「重すぎる」、軽口と当然視は「失礼」、約束破りは最も「失礼」 | 修復期の5つの回答 | 4つの述語、反省の知覚、再発の危険 |
| H6 | 親しい関係では、修復期の軽口の「失礼」が弱まる | 関係 × 軽口 | 失礼 |
| H7 | 過度なぼかしは「重すぎる」より信頼意図を下げる | ぼかしすぎ vs 較正された構え | 重すぎる、信頼意図 |
| H8 | 同じ但し書きが、失敗の前と修復期では「釣り合う」を上げ、謝罪の場面では「足りない」「失礼」を上げる。謝罪の場面では、詫びより前に置くと後に置くより悪い | 但し書きの局面（前・謝罪・修復期）× 回答の中の位置 × 種類（範囲の明示・責任の限定） | 4つの述語、信頼意図 |
| H9 | 「釣り合う」は、三つの否定の min で積よりよく表せる | 評定者自身の4つの答え | 釣り合う（方法論） |

各仮説について、向き（片側か両側か）、主指標、効果の最小の大きさ（たとえば所属度の差 0.1）、検定の方法、多重比較の扱い（Holm 法）を、データを集める前に固定します。

### 8.2 項目の組

すべての組で、土台（依頼・失敗・謝罪）をそろえ、操作する部分だけを変えます。領域は、コード修正・予定の操作・事実の回答・ファイルの操作の4つです。

| 組 | 操作 | 水準 |
|---|---|---|
| A 失敗の前の構え | 失敗の前のAIの発話 | 控えめ／中立／自信満々／断言＋懸念を退ける／「確認済み」と偽る |
| | 謝罪 | 過信に触れない・触れる（控えめの水準では、負担に触れない・触れる） |
| B 修復期 | 受け入れの後の回答 | 詫びなしで慎重に作業／また詫びてから作業／はしゃぐ・軽口／許しを当然視／前の約束を破る |
| | 関係 | 親しい（くだけた口調、絵文字）／普通 |
| | 傷の深さ | 軽い失敗の後／約束を破った後の受け入れ |
| C 但し書きの局面 | 同じ但し書きの置き場所 | 失敗の前の発話／謝罪の回答（詫びの前・後）／修復期の回答 |
| | 但し書きの種類 | 範囲の明示／責任の限定 |
| D 錨 | — | 既存の作例とベンチマークから数問（旧来の結果とのつながり、尺度の使い方の確認） |

項目は `examples/scenes-v09.json` に、場面・回答・操作の水準・観察（6章の観察者の集団で作る）をそろえて置き、シミュレータとキットで同じ項目を使います。

### 8.3 割り付け

同じ人が同じ土台の別の水準を続けて見ると、比較が露骨になり、評定が操作の意図に引きずられます。そこで、**一人の評定者は、一つの土台について一つの水準だけを見る**ようにします。

- 土台×水準の表をラテン方格で複数のリストに分け、評定者IDのハッシュでリストを決めます。どのリストも、すべての水準を（別の土台で）同じ数だけ含みます。
- 錨の項目は全員が見ます。再評定の項目は各リストから2問ずつ置きます。
- 出題順は、評定者ごとに乱数で並べます。

### 8.4 評定ページ

| 要素 | 内容 | 目的 |
|---|---|---|
| 会話の表示 | 失敗の前のAIの発話と、受け入れの発話を含めて、複数ターンを省略せずに表示する | 構えと経緯を評定者に見せる |
| 主の設問 | 4つの述語×5段階 | — |
| 信頼意図（全項目） | 「このAIに、この先も任せられそうだと感じますか」（1〜5） | 4つの述語の外の頼れなさを測る（H4、H7、H8） |
| 反省の知覚・再発の危険（修復期の組） | 「この返答から、反省が続いていると感じますか」「同じようなことがまた起きそうだと感じますか」（1〜5） | 修復期の仕組みを測る（H5） |
| 操作の確認（各項目の最後） | 「失敗の前、AIはどのくらい自信を持って言っていましたか」（0〜3） | 構えの操作が伝わったか。主の評定の後に置き、主の評定を誘導しない |
| 注意の確認 | 指示どおりに答える項目を1問 | 雑な回答の除外（基準は事前登録） |
| アンケート | 「断言して外す人は、控えめに言って外す人より信用できない」「『確認済み』と言われたら、自分では確かめない」「謝られた後は、早くいつもどおりに戻ってほしい」「一度許したことを何度も謝られると、かえって負担だ」「謝るときの『念のため』の一言は、言い訳に聞こえる」「AIを仕事でよく使う」（1〜5） | `overclaim`、確かめの頼り方、控えの好み、詫びの繰り返しの負担、但し書きへの感じ方、AI の利用経験 |

1人あたりの項目数は 24〜30 問（約30分）に抑えます。

### 8.5 人数と検出力

- 評定者 40〜60 名を目安とします。各評定者が A・B・C の組から計 24 問前後と錨（D）4 問を見ると、1つの水準あたり約 60〜90 件の評定が集まります。
- 検出力は、シミュレータ自身で見積もります（`blind.py power`）。母集団から合成評定者を抜いて項目に答えさせ、事前登録した検定で仮説の効果を検出できる割合を、人数を変えて計算します。モデルが正しくない可能性に備えて、予測の半分の効果でも検出できる人数を選びます。

### 8.6 分析

- 主指標は5章の規則（RPS、二乗誤差、場面と評定者の二元ブートストラップ）です。
- 仮説の検定は、土台ごとの水準間の所属度の差を、評定者と土台で層別した並べ替え検定で行います。混合効果の順序回帰が要る場合は、CSV に書き出して外部のソフトで行います。
- 操作の確認で、構えが伝わらなかった評定者の割合を報告します。除外はせず、感度分析で扱います。
- 同じ項目をシミュレータに通し、各仮説の向きと大きさが人間と一致するかを報告します。一致しない仮説は、受け手モデルの該当の規則を見直す候補です。

## 10. 採否の基準

5章の手続き（場面単位の交差検証、分割の外側の採点）で判断します。

| 対象 | 基準 |
|---|---|
| 評価指標 | 「常に釣り合う」がシミュレータより良くならない。基準とスキルスコアが表に並ぶ |
| 控えの時間軸モデル（修復期） | ベンチマークの修復期24回答の Brier が v0.8 より良く、差の区間が 0 を含まない。修復期以外の回答の成績を悪くしない |
| 控えの時間軸モデル（失敗の前の構え・但し書き） | 評価キットで、事前登録した仮説 H1〜H4・H7・H8 の向きを人間の評定が支持し、シミュレータの予測がその向きと一致する。ベンチマークの成績を悪くしない |
| 観察者の集団 | 集団の平均を使ったシミュレータの Brier が、各変種単独のどれにも負けない。LLM の観察での「釣り合う」の不足が半分以下になる |
| 出どころごとの較正 | 分割の外側で、較正なしより良い |
| 全体 | 「条件だけ」の基準に対するスキルスコアが正で、区間が 0 を含まない |

## 12. 未解決の問い

- 控えの必要量が、関係の親疎でどう変わるか。親しい関係では、早めに普段の調子に戻ることがむしろ修復の合図になる可能性があります（`warmth` との関係。H6 で一部を確かめる）。
- 修復期が何ターン続くか。受け入れからのターン数で、控えの必要量が減っていく可能性があります。
- ユーザーが自分で確かめる手段を持っていたかで、失敗の前の控えめさや但し書きへの寛容さが変わる可能性があります。
- AIの「確認済み」を、ツールの実行記録と照合できる場合は、観察ではなくコードで判定します。照合できない場合の扱いは、観察者の集団の判断に任せます。
- 但し書きが多すぎる場合（失敗の前でも、何でも「念のためご確認ください」と言う）は、それ自体が負担や頼れなさになりえます。失敗が起きていない場面の評価はこのシミュレータの範囲の外ですが、SHAZAI Rules の側では扱う価値があります。
- 観察者の集団の平均でも、全変種が共有する系統的な偏りは残ります。その場合は、少数の人の観察（金ラベル）で欄ごとに較正します（[JEV_DESIGN.md](JEV_DESIGN.md) 5.6節）。
- 反応モデルの β が評定者ごとに違う場合（断定的に答える人と迷う人）、β を型の性質に加えるかどうか。
