# 設計思想と目的

このシミュレータの設計の「なぜ」をまとめた文書です。設計を変えるときは、まずこの文書の原則と決定記録に照らしてください。仕組みの詳細は [ARCHITECTURE.md](ARCHITECTURE.md)、控えの時間軸と評価の方法は [METHODS.md](METHODS.md)、根拠となる研究は [EVIDENCE.md](EVIDENCE.md)、検証結果は [VALIDATION.md](VALIDATION.md) と [EVALUATION.md](EVALUATION.md) にあります。版ごとの経緯は [HISTORY.md](../../HISTORY.md) にまとめています。

## 1. 目的

**誠実に見える謝罪のかたち、つまり受け手に「釣り合っている」と感じさせる振る舞いとは何か**を、受け手の多様さを含めて測ることです。

- 出発点は、SHAZAI Rules（AIの謝罪を日本の文化に合わせる指示）のベンチマークです。そこでは、LLMペルソナによる評定が筆者の評定と大きくずれていました。
- 本シミュレータでは、「誠実に見えること」と「釣り合っていると感じること」を実質的に等価なものとして扱います（所有者の判断）。ただし研究上は両者が分かれる場面があります（[EVIDENCE.md](EVIDENCE.md) E-01）。分かれる場面では、主の出力は「釣り合い」とし、必要に応じて誠実さを副指標として出します。
- 対象は、AIアシスタントの現実のタスクでの謝罪、AIキャラクターの謝罪、物語の登場人物の謝罪です。

### 範囲

- **外から見える振る舞いだけ**を扱います。内面描写や、地の文による評価（「心から反省していた」など）は使いません。
- **観測時点（その謝罪の場面）までの経緯**を使います。その後の場面で約束が守られたかどうかは、その時点の評価には入れません（後の場面を評価するときに、経緯として入ります）。

## 2. 設計原則

**P1 観察と評価を分ける。** LLMには、回答に何が書かれ、何が描写されているかを記録させるだけにします（層A）。どう受け取るかは、コードで書いた受け手モデルが計算します（層B）。LLMの寛容さ、長い回答を好む癖、書き手の善意を前提に読む癖を、評価の段階から締め出すためです。

**P2 一つの判定ではなく、反応の分布と程度を出す（ファジィ前提）。** 受け手の母集団を性質の分布として持ちます。受け手一人ひとりは、「失礼／足りない／釣り合う／重すぎる」の4つの述語それぞれに、どの程度当てはまると感じるかを所属度（0〜1）で持ちます。人によって違うこと（確率）と、一人の中で「少し失礼だが、だいたい釣り合う」と感じること（程度）は別の現象なので、前者は母集団の分布で、後者は所属度で表します。出力の主は平均所属度で、裾として「失礼と感じる人の割合」（所属度0.5以上の人の割合）も出します。謝罪は一番怒っている人に通用するかで決まるので、裾も重視します。

**P3 受け手は属性ではなく態度の軸で作る。** 年代や性別のペルソナをLLMに演じさせると、集団の姿を取り違え、平板にします（EVIDENCE A-01）。そこで、研究で効く向きが示された性質（察しの感度、当事者として読む度合い、修復の重視、重さへの耐性など）で受け手を表します。特定の評定者（筆者を含む）は「正解」ではなく、母集団の中の一点として扱います。

**P4 減点は足し合わせ、一つの失敗で崩れうるようにする。** 謝罪の評価は平均点ではなく、一番悪い一文や一つの振る舞いで崩れます。失点を合計した無礼さから「失礼」の所属度を出し、単独で最大級の失点（相手への指摘）だけで所属度が0.5に届くように所属度関数を置きます。

**P5 無礼さ・不足・過剰を別々の軸で持つ。** 失礼は無礼さ（失点の合計）から、足りないは謝罪の中身の不足量から、重すぎるは許容を超えた重さから、それぞれ独立に出します。三つの述語は排他的ではないので、「重すぎるのに足りない」（土下座はするが直していない）や「少し失礼だが足りている」も表せます。釣り合うは、三つの否定の論理積（t ノルム、既定は min）です。

**P6 経緯で受け取り方が変わる（ヒステリシス）。** 信頼は損なわれやすく戻りにくいので、同じ回答でも、そこに至る経緯で受け取られ方が変わります。経緯は観測時点までの場面から読みます。受け手は謝罪を、失敗の前・謝罪の場面・修復期という時間の中で見ます。失敗の前にどれだけ確かに言ったか、修復期に控えがふるまいに表れているかも、経緯として受け取り方を変えます（[METHODS.md](METHODS.md) 3章）。

**P7 シグナルの信用度は場面の枠組みで決まる。** 同じ「しょんぼり」でも、物語の中の登場人物（またはAIキャラクター）の身体として描かれれば本物の合図として読まれます。一方、現実のタスクで失敗したAIのト書きや顔文字は、本物の代償を伴わない仮想の身体なので、受け取り方が人によって大きく分かれ、失敗が深刻なほど効きが落ちます。代償も同様で、物語の中では作中の代償が本物として働きますが、現実のタスクでは現実の代償（実際の作業、点検、返金など）しか代償として数えません。

**P8 シグナルの意味は文脈で反転しうる。** 照れや気まずさの表出は、過失が明白なら相手をなだめますが、曖昧なら後ろめたさの自白として読まれます。謝罪中の笑みは不誠実の信号ですが、物語の中の軽い失敗では愛嬌として受け取る人もいます。

**P9 すべての規則を根拠に対応づける。** 規則ごとに、根拠となる研究や事例を [EVIDENCE.md](EVIDENCE.md) に記録し、確度（強・中・仮説）を付けます。数値の大きさは多くが事前値で、人間のデータで推定していないことを明示します。

**P10 互換性を保つ。** 観察の欄は、観察されていないときの既定値で、その欄がない観察と同じ結果になるようにします。受け手の性質を足すときは別の乱数列で引き、ほかの性質の抽出を変えないようにします。ただし、評定の論理そのものを組み直すときは、この原則より論理の一貫性を優先し、[HISTORY.md](../../HISTORY.md) に記録します。

**P11 確率とファジィを混ぜない。** 同じ不確かさを二重に数えないために、乱数は母集団の抽出（人による違い）にだけ使い、一人の判定は決定的にします。一人の中の程度は、所属度関数のなだらかさと、「不満が明確／強い」の境界のなだらかさ（ソフトな境界）で表します。観察の確率（[JEV_DESIGN.md](JEV_DESIGN.md) 5.4節）や観察者どうしのばらつき（[METHODS.md](METHODS.md) 6章）を受け手の違いとして流すかどうかも、同じ原則で判断します。

**P12 予測は確率分布として、真に適正なスコアリング規則で測る。** シミュレータの主張は「受け手の母集団がこう分布する」なので、評価では母集団から予測分布を作り、確率を正直に出したときに最良になる規則（Brier・対数損失・RPS）で採点し、必ず基準と比べます。データを見て決めるものは、場面単位の交差検証の内側で決めます（[METHODS.md](METHODS.md) 5章）。

## 4. 未解決の問い

- 所属度関数の中心となだらかさ（`population.json` の `judgment`）は事前値です。人間の5段階の評定から推定する必要があります。
- 「釣り合う」を三つの否定の min で作るか積で作るかは、人間が直接答えた「釣り合う」との比較で決めます。どちらでもない場合（たとえば、釣り合うが他の三つと独立に動く）は、述語の構成そのものを見直します。
- 評定者が5段階を等間隔の所属度（0／0.25／0.5／0.75／1）として使っているかは確かめていません。
- 型の比率と性質の強さは事前値です。20〜30人程度の評定で、型の混合を推定する必要があります。
- ショックの表出の効果は、直接の研究を確認できていません（仮説）。
- 経緯の効果は、経緯だけを変えた場面の組がないと識別できません（[VALIDATION.md](VALIDATION.md)）。
- 控えの時間軸の係数と、傷が20ターンで消えるという仮定は事前値で、人間のデータで確かめていません（[METHODS.md](METHODS.md) 10章）。
- 「誠実に見えるか」と「釣り合うか」が分かれる場面で、どちらを主にするかは用途によって変わりえます。
- 物語の読者（第三者の視点）と、ゲームのプレイヤー（謝られた本人の視点）では、受け手の母集団そのものが違う可能性があります。
