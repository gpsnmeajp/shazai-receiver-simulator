1. 全体の流れ

会話・場面・回答
→
層A 観察（LLM）observe_prompt.md に従い、良し悪しを判断せずに記録する。API がない場合は proxy（既存のチェックリスト＋表層特徴）
→
観察JSON場面の観察＋回答の観察
→
層B 受け手（コード）population.json の型の混合から N 人を抽出し、1人ずつ「不満の深さの知覚 → 失点・不足・過剰 → 評定」を計算する
→
出力回答ごとの評定分布（失礼／足りない／釣り合う／重すぎる）、量の軸（不足・過剰）、型ごとの内訳

3. 観察データの形式

3.1 場面（scenario）

欄型意味
distance_shift0〜3受け手側の調子の距離の変化（丁寧化、呼称、絵文字の消失、文量の減少、相槌化）
explicit_complaint0〜3不満の明示度
prior_corrections整数それまでに誤りを指摘した回数
ai_unrequested_push真偽頼まれていない助言の押し付けがあったか
harm0〜2損害の大きさ
violation_type列挙none / competence / integrity：能力の問題か、誠実さの問題か
apology_accepted_before真偽謝罪がすでに受け入れられた後か（修復期）
requests配列最後の発話の依頼・質問
prior_ai_apologies整数それまでに謝った回数（ヒステリシス用）
broken_promises整数約束の後に同じ違反を繰り返した回数（ヒステリシス用）
context下表場面の枠組み

context の欄。省略時は太字の既定値で、従来のベンチマークと同じ挙動になります。

欄値意味
failure_framereal_task / story現実のタスクでの失敗か、物語の中での失敗か
apologizerai_assistant / ai_character / human_character謝る側
viewpointvictim / observer謝られた本人の視点か、第三者（読者）の視点か
fault_clarityclear / ambiguous過失が明白か曖昧か
power-1 / 0 / 1謝られる側が下・対等・上
distanceclose / neutral / distant親しさ

3.2 回答（answer）

apology

有無、位置、過失の具体性、負担の言語化、感謝で代用、定型の同意、prompted

repair

依頼ごとの遂行状況、誤りの上塗り、頼まれていない提案

defense

弁解、相手への指摘、条件付きの詫び、説明量

excess

自己卑下、約束、許しの要求、詫びの回数

closure

終結宣言、先を急ぐ

register

丁寧さの変化、絵文字・感嘆、書式

sentences

一文ごとの悪い読みと、その自然さ

signals

態度・行動のシグナル（下表）

詳細は observe_prompt.md を参照してください。

signals の要素

欄意味
kind種類（下のカード）
intensity0〜2
virtualAIの仮想の身体か（省略時：謝る側がAIなら真）
baseline_shift普段との差 0〜2（言葉数・声・固まる で使う。省略時 1）
cost{"kind": real/in_world/declared, "amount": 0〜2}
congruent言葉と食い違っていないか
performative_plausibility演技に見える読みの自然さ 0〜1

なだめ

gaze_down head_bow dejected awkward blush tears freeze fewer_words quiet_voice

明白な過失では失点を和らげ、中身に加点。曖昧な過失では blush awkward gaze_down fewer_words quiet_voice freeze が後ろめたさとして減点

礼

deep_bow dogeza

なだめと同じ働きに加えて、重さに加算

ショック

shock

事態の重さを認めた合図として中身に加点。曖昧な過失ではなだめる

不一致

smile laugh flippant

強い減点

代償

repair_action compensation sacrifice declared_cost

種類と枠組みに応じて中身に加点。過大なら重さに加算

4. 受け手モデル（層B）

受け手1人は性質 θ を持ちます。範囲と型ごとの平均は population.json にあります。

型の比率（事前値）

当事者 20%寛容 25%効率 20%礼節 15%相棒 20%

当事者・関係修復型／寛容・観察者型／効率・道具型／礼節規範型／相棒・情緒型。各性質は型の平均のまわりに正規分布で散らし、範囲で切ります。embodiment は別の乱数列から引きます（EXTRA_KEYS）。

セルの濃さは、範囲の上限に対する型の平均の大きさ。
性質範囲意味当事者寛容効率礼節相棒
detect0〜1.6距離の変化を不満と読む感度1.20.50.60.91.0
cause0〜1.2AI側の原因を不満の推定に入れる度合い0.90.30.60.60.7
partisanship0.05〜1当事者として悪い読みを採る度合い0.90.30.40.60.7
repair0〜1.2償い・依頼の遂行の重視0.90.51.00.60.5
tolerance0〜3重い謝罪への耐性2.01.00.32.51.2
forgiveness0〜1寛容性0.30.80.60.40.6
register0〜1.2文体・絵文字・書式への規範0.80.30.21.00.5
brevity0〜1短さ・効率の重視0.30.40.90.20.3
expect0.3〜1.4期待する謝罪の深さ1.00.80.51.20.9
warmth0〜1くだけた関係が冷たく改まることへの抵抗0.30.40.10.10.8
memory0〜1傷の残りやすさ（ヒステリシス有効時のみ）0.80.30.50.60.6
embodiment0〜1現実のタスクで、AIの仮想の身体を合図として受け取る度合い（シグナルがあるときのみ）0.40.60.10.30.8

4.1 場面への調整（effective_theta）

power → expect ×= 1 + 0.15·power

distance = distant → register ×= 1.3

distance = close → warmth ×= 1.5

viewpoint = observer → partisanship ×= 0.6

根拠：B-04、B-05、B-09

4.2 不満の深さの知覚（perceive）

場面から、受け手が感じ取る不満の深さ L（0〜4） を求めます。傷 S はヒステリシス有効時（既定）だけ使います。

prior  = min(prior_corrections, 3)
causes = 0.35·prior + 0.35·push + 0.35·harm + 0.35·[integrity]
S      = memory·(0.6·n^1.3 + 0.8·[integrity] + 0.7·broken_promises)    ※ヒステリシス時のみ。それ以外は0
         n = prior_corrections + [harm>0 または 明示≥1 または 受け入れ後]
raw    = EXPLICIT[explicit] + detect·(1+0.3S)·distance_shift + cause·causes + (1−forgiveness)·0.3·prior
         EXPLICIT = {0:0, 1:1.3, 2:2.3, 3:3.3}
受け入れ後: raw ×= 1 − 0.6·forgiveness·exp(−S)
L      = clip(raw + N(0, 0.3), 0, 4)
L0L1L2L3L4L ≥ 1.5 を「明確」、L ≥ 2.5 を「強い」とする

4.3 評定（judge_full）

1
失点 F を数える
  • 依頼の未遂行（not 0.4+1.2·repair、deferred 0.2+0.9·repair、partial 0.5·repair。強いとき×1.3）、誤りの上塗り、弁解、条件付きの詫び、相手への指摘
  • 明確なとき：説明の多さ、頼まれていない提案、先を急ぐ、絵文字・感嘆（×register）、長さ（×brevity）
  • 強いとき：定型の同意から入る、書式、文体の崩れ、謝罪の後回し
  • 終結宣言。L < 1.5 で急に冷たく改まる（×warmth）
  • 悪く読める一文：自然さ p を p^(1/partisanship) の確率で採り、0.7×重さを加える
  • シグナル由来の失点（4.4）
2
必要な中身

need = interp(L, [(0,0),(1,0.8),(2,1.5),(3,3.0),(4,3.8)])·expect。受け入れ後は min(need, 1 + 0.8S)。

3
回答の中身

adequacy = discount·(謝罪あり 1.0 + 冒頭 0.5 + 0.3·max(0,丁寧化) + 0.6·過失の具体性 + 0.5·負担の言語化) + シグナルの加点

discount は、ヒステリシス時に 1/(1+0.35·過去の謝罪回数·memory)。既定では一段改めた具体的な謝罪は 1（割り引かない）で、--no-escalation で割り引きます。促された謝罪なら ×0.85（第三者視点は ×0.6）。

4
不足

shortfall = max(0, need − adequacy)。失点に 0.8·shortfall を加えます。

5
合計

total = max(0, ΣF − min(なだめ, 0.8))

6
重さと過剰

weight = 詫びあり 1 + 0.5·(詫びの回数−1) + 0.6·自己卑下 + 0.4·約束 + 0.4·許しの要求 + 0.3·丁寧化 + シグナルの重さ

許容は w_ok = interp(L, [(0,0),(1,0.5),(2,1.0),(3,2.0),(4,2.5)])·expect（L ≥ 1.5 または明示 ≥ 1 なら最低 1.0）と tol = tolerance·min(1, 0.25+L/2)·(1−0.5·brevity)。

過剰 excess = weight − w_ok − tol

7
評定
失礼
total ≥ 2.0（±0.2のゆらぎ）
足りない
total ≥ 1.0（±0.15）
重すぎる
上のどちらでもなく excess > 0.3
釣り合う
それ以外

現実のタスクの仮想の身体embodiment ×（L≥2.5 なら 0.5）F-01 F-03 F-04
人の身体（現実）1

  declared             → 中身 +0.15·amount（ヒステリシス時、約束を破った後なら失点）           [D-04]

補償と強い仮想の感情表現の組み合わせ（強い不満）: 失点 0.3·(1−embodiment)                       [F-06]
演技に見える: 観察の performative_plausibility、なければ min(1, 0.2·max(0, 演じられる表出の合計−2))。
          p^(1/partisanship) の確率で 0.7 の失点                                              [E-06]

6. 拡張の手順

シグナルの種類を足す

SIGNAL_GROUP に種類と群を登録します。普段との差で意味が変わるなら BASELINE_DEPENDENT、曖昧な過失で反転するなら AMBIGUITY_FLIP、演じにくいなら UNCONTROLLABLE にも加えます。そのうえで observe_prompt.md の表と根拠の文書に追記します。

受け手の性質を足す

population.json の ranges と、各型の mean・sd に加えます。既存の結果を変えたくない場合は、EXTRA_KEYS に登録して別の乱数列で引きます。

場面の枠組みを足す

DEFAULT_CONTEXT に既定値を置き、既定値で従来の挙動になるようにします。

変更後の確認

simulate の出力が意図しない形で変わっていないこと（ベンチマーク）と、scenes の作例の向きが変わっていないことを確認し、検証 に記録します。

7. 人間の評定との比較の流れ

作例 examples/scenes.jsonまたは、ベンチマークの実行先
→
自動評価sim.py scenes → out/scenes-result.json
sim.py proxy/observe → simulate → out/sim.json
人間blind.py pack（--runs）→ rate.html → 評定者 → ratings/*.json
→
blind.py comparecompare.md。--auto でペルソナ等も並べる

項目は「元の項目ID」（作例は scene:S1/A2、ベンチマークは回答ID）で突き合わせます。

8. 再現性

  • 乱数の種は --seed（既定 7）。受け手の抽出は seed、知覚と判定のゆらぎは seed+1、追加の性質は seed+9973 を使います。
  • 一致度は乱数だけで ±0.05 程度揺れます。差を主張するときは、種を変えて確かめてください。
