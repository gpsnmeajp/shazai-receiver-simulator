1. 要約

控えの時間軸

謝罪の受け取られ方は、失敗の前・謝罪の場面・修復期のどこで、どんな構えを見せたかで変わる。失敗の前の自信の度合い、謝罪の場面の言い訳、修復期のふるまい、免責の但し書きを、局面ごとに観察し、局面に応じた働きで受け手モデルに入れる。

統計的に正当な評価

母集団から作った予測分布を、真に適正なスコアリング規則で採点し、基準と比べる。データを見て決めるものは交差検証の内側で決める。

観察者の集団

層Aを、観察方針・場面の事実の前提・モデルの系統に幅を振った複数の観察の平均にする。

較正と観察の固め

所属度関数を観察の出どころごとに較正し、場面の観察を定義とコードで固める。

人間の評価キット

設計の仮説を、操作した項目の組と事前登録した検定で、日本の受け手に確かめる。

3. 控えの時間軸モデル

3.1 考え方

謝罪は一度の出来事ですが、受け手はその前後を含めた時間の中で相手を見ています。

局面 1

失敗の前

どれだけ確かに言ったか

  • 控えめに言っていた失敗は「予告されていた失敗」
  • 断言していた失敗は「言ったことを信じてよいか」を傷つける
  • 「確認済み」と偽っていれば欺瞞
局面 2

謝罪の場面

負担と構えの誤りを認めるか

  • 相手の負担への言及と、過失の承認
  • 断言して外したなら、過信そのものへの言及
  • 但し書きや事情の説明は言い訳に聞こえる
局面 3（ρ）

修復期

反省がふるまいに表れているか

  • 調子を急に戻さない、確かめを挟む、前の約束を守る（控え）
  • 詫びの繰り返しは負担
  • 軽口・許しの当然視は失礼

時間 →

同じ振る舞いでも、局面によって働きが逆になります。その典型が免責の但し書きです。受け手モデルは局面を真理値で持ち、振る舞いの働きを局面で切り替えます。

もう一つの前提は、日本の謝罪の働きです。日本の謝罪は、責任の承認よりも、相手の負担を認め関係を保つ反省の表明として働きます（Maddux ら 2011）。そこで謝罪の中身を二つの成分に分けて扱います。

過失の承認

apology.specific_fault（＋過信への言及）。自分の何が誤りだったかを認める。失敗の前に控えめだった場合は、必要が下がる。

負担への言及

apology.names_burden。相手が負った手間・時間・損失を認める。責任の有無によらず必要で、控えめさでは下がらない。

3.2 局面

局面判定真理値
失敗の前会話の履歴のうち、後で指摘された失敗を含むAIの発話と、それより前の発話観察（caused_failure）から決まる
謝罪の場面判定する回答のうち、修復期でない部分1 − ρ
修復期謝罪が受け入れられた後の回答ρ（観察者の集団で「受け入れ後」と判断した割合。0〜1）

ρ を度合いで持つので、受け入れがあいまいな場面（「…わかりました」だけの返事など）では、謝罪の場面と修復期の働きが混ざります。

3.3 失敗の前の構え

欄（prior_stance）値記録すること
turns配列AIの発話ごとに {turn, confidence, caused_failure}。confidence は 0 不確かさを明示／1 中立／2 自信あり／3 断言・強気
dismissed_concern真偽ユーザーの懸念や疑問を退けて進めたか
claimed_verification真偽「確認済み」「テスト済み」など、確かめたと述べていたか
verification_false真偽／不明確かめたと述べたのに、実際には確かめていなかったことが明らかか（実行記録と照合できるならコードで判定）
salient0〜1失敗が断言と明らかに食い違うか、ユーザーがそれに触れたか
自信           c = max(confidence of caused_failure の発話) / 3       （観察者の集団で平均。0〜1）
控えめの度合い h = caused_failure の発話のうち、不確かさを明示していた割合（免責の但し書きを含む）
気づかれやすさ v = 0.5 + 0.5·salient
過信の差       G = v·c·(1 + 0.5·[dismissed_concern])                  （0〜1.5）
  • 過信の差が大きいほど、受け手は失敗をAIの原因として読み、不満が深くなる。控えめだった場合は浅くなる（Tenney ら 2007、Sah ら 2013）。
  • 断言して外すことは信頼の根を傷つける。能力の違反と誠実さの違反の中間として、信頼の傷に加える。
  • 確かめたと偽っていた場合は欺瞞。欺瞞を伴う違反の後の信頼は、約束・謝罪・一貫した行動があっても完全には戻らない（Schweitzer ら 2006）。この分は、受け入れ後にも減らない「残る傷」として分ける。
  • AIの自信のずれは利用者に気づかれにくいので（Li ら 2024）、過信の効果は気づかれやすさ v で弱める。

3.4 謝罪の場面の構え

欄（stance）値記録すること
acknowledges_overclaim0〜2失敗の前の言い切り・確かめなかったことに触れているか
confidence_now0〜3この回答での自信の度合い
calibrated真偽確かめたことと確かめていないことを区別して述べているか
over_hedging0〜2必要以上のぼかし・自信のなさの表明の量
  • 過信の差が大きいときは、過信そのものへの言及（「確かめずに断言してしまいました」）が過失の承認の一部として必要になる。
  • 過信で外した直後に同じ強さで言い切ると「懲りていない」。不確かなのに自己高揚すると性格の評価が下がる、という結果（林ら 2024）と同じ向き。
  • すべてを過度にぼかすと、主に頼れなさとして受け取られる（林ら 2024、Kim ら 2024）。4つの述語の外の評価なので、別の出力 reliability とし、述語には「確かめの負担を相手に戻す」分だけを小さく重さとして数える。
  • 確かめたことは言い切り、確かめていないことは確かめると言う較正された構えは、謝罪の場面でも修復期でも控えの中身として数える。

3.5 免責の但し書き：局面で働きが逆になる

免責の但し書き（「保証はできません」「念のためご確認ください」「〜の可能性があります」）は、置かれた局面によって働きが逆になります。失敗の前では構えの較正、謝罪の場面では言い訳（日本の受け手は説明を挟まない直接の謝罪を好む：既存 C-02。謝罪で最も重要なのは責任の承認：既存 C-01）、修復期では確かめを挟む配慮です。

種類例失敗の前謝罪の場面修復期
範囲の明示「この部分は未検証です」「〜の可能性があります」有用控えめの度合い h を上げる減点言い訳（弁解に加える）有用較正された構え
確かめの申し出・実施「実行前に確認します」「確認しました：〜」有用h を上げる中立〜有用これからの行動。ただし詫びより前に置くと「先を急ぐ」有用配慮
責任の限定「保証はできません」「最終的にはご自身でご確認ください」有用（小）h を少し上げる強い減点責任の押し戻し有用（小）範囲の共有。確かめをすべて相手に戻す言い方は小さく減点

回答の中の位置

謝罪の場面で、但し書きが詫びより前にあると、言い訳が先に立つので重く数え（×1.5）、謝罪が後回しになった扱いにも加える。詫びと修正を終えた後の範囲の明示は軽く数える（×0.7）。

観察（disclaimer）

文の単位ごとに、但し書きの種類を none / scope / verify / liability で記録する。会話の履歴のAIの発話にも付ける。局面と回答の中の位置はコードで決め、観察者は種類だけを判断する。

局面ごとの働きは、それぞれ既存の根拠や自信と誤りの研究で支えられますが、「同じ但し書きが局面で働きを逆にする」こと自体を位置を操作して比べた研究は見つかっていません。全体としては仮説で、評価キットの仮説 H8 で確かめます。

3.6 修復期の控え

欄（restraint）値記録すること
tone_reset0〜2不満を表明される前の調子へ急に戻った度合い（0 抑えている、2 何もなかったような明るさ・はしゃぎ）
levity_about_incident真偽失敗そのものを冗談・軽口にしているか
presumes_forgiveness真偽許されたことを当然視する言い方があるか
care0〜2目に見える配慮の量（確かめを挟む、慎重な言い回し、手間を減らす工夫）
promise_keptkept / broken / na以前に約束した振る舞いを、この回答で守っているか
revisits_incident0〜2頼まれていないのに事件を蒸し返す量
re_apology0〜2改めて詫びている量
  • 修復期に信頼を戻すのは、詫びの繰り返しではなく、信頼に足る行動の一貫（Schweitzer ら 2006）と、反省している・また害されないと知覚させるふるまい（Dirks ら 2011、McCullough ら 2014）。日本では違反を改められるものと見る傾向がある（Maddux ら 2011）。
  • 反省の信号は能力の違反の後で重く受け取られる（Dirks ら 2011）。一方、誠実さの違反の後の謝罪は日本人の方が信頼を回復させた（Maddux ら 2011）。向きが一部逆なので、違反の種類による調整は小さくする。
  • 約束破り・許しの当然視・軽口は失点、詫びの繰り返しと蒸し返しは重さ。受け入れ後の軽口と詫びの繰り返しは仮説。

3.7 受け手モデル

既存の式（仕組み 4章）に、次を加えます。係数はすべて事前値です。v0.8 の need = min(need, 1 + 0.8·S) は廃止し、修復期の必要量は謝罪の言葉ではなく控えで測ります。

知覚と信頼の傷（傷には 3.9 節の減衰 d を掛ける）

raw   += cause·(0.5·G − 0.3·h)
raw   ×= 1 − ρ·0.6·forgiveness·exp(−(S + S_dec))                         （受け入れ後の不満の減り）
S      = memory·(0.6·n_eff^1.3 + d·(0.8·[integrity] + 0.7·broken_promises + 0.6·overclaim·G))
S_dec  = memory·0.8·[verification_false]·(f + (1 − f)·d)                （欺瞞の傷。減衰しても f = 0.5 が残る）

不足（「足りない」へ）

share_fault = 0.5
need_fault  = need_apology·share_fault·(1 − 0.5·h) + 0.5·G·overclaim      （過失の承認）
need_burden = need_apology·(1 − share_fault)                              （負担への言及。h では下がらない）
ad_fault    = 0.5·詫びの言葉 + 0.6·specific_fault + 0.5·acknowledges_overclaim·min(1, G) + 0.5·シグナルの加点
ad_burden   = 0.5·詫びの言葉 + 0.5·names_burden + 0.5·シグナルの加点
gf = need_fault − ad_fault、gb = need_burden − ad_burden
Sa = max(0, gf + 0.5·min(0, gb)) + max(0, gb + 0.5·min(0, gf))         （一方の余りは他方の不足を半分だけ埋める）

need_restraint     = (0.3 + 0.5·(S + S_dec) + 0.4·G)·expect
adequacy_restraint = (0.35·care + 0.4·(2 − tone_reset)/2 + 0.5·[promise_kept=kept] + 0.3·[calibrated]
                      + min(0.3, 0.15·Σ有用な但し書き))·(1 − 0.3·[integrity])
Sr                 = max(0, need_restraint − adequacy_restraint)

shortfall = (1 − ρ)·Sa + ρ·Sr

失点（「失礼」へ）

懲りていない           0.6·G·[confidence_now ≥ 2]·overclaim
但し書き（謝罪の場面）    (1 − ρ)·(0.4·scope + 1.0·liability)·(1.5 if 詫びより前 else 0.7)   （文ごと）
確かめ（謝罪の場面）      (1 − ρ)·mid·0.3·verify（詫びより前のときだけ。「先を急ぐ」に加える）
約束破り（修復期）       ρ·(1.0 + 0.5·memory)·[promise_kept=broken]
許しの当然視            ρ·0.6·(1 + S + S_dec)·presumes_forgiveness
軽口                   ρ·0.5·levity_about_incident·(1 − 0.5·warmth)
調子を急に戻す           ρ·0.3·(S + S_dec)·max(0, tone_reset − 1)

重さ（「重すぎる」へ）と別の出力

詫びの繰り返し・蒸し返し  ρ·0.4·(re_apology + 0.5·revisits_incident)·(1.5 − 0.5·tolerance/3)
確かめの負担を戻す       0.15·over_hedging·(1 − 0.5·min(1, G)) + ρ·0.1·min(1, Σliability)
reliability            1 − 0.3·over_hedging − 0.4·G·[confidence_now ≥ 2] − 0.5·[verification_false]·(f + (1 − f)·d)

観察者の集団の平均では、真偽は割合、列挙は票の分布になります。受け手モデルはどの値もそのまま真理値として使います。restraint が観察されていなければ、配慮は普通（care 1）、調子は抑えている（tone_reset 0）として扱います。

3.8 受け手の性質 overclaim

過信を罰する度合い（0〜1）。謙遜は日本に固有の規範ではなく文化に共通の価値で、違うのは程度と仕方です（山口ら）。日本人らしさの性質ではなく、どの型にも幅のある個人差として置き、既存の性質の抽出を変えないよう別の乱数列で引きます。

型平均理由
当事者・関係修復型0.8言われたことを信じて動いた分だけ、裏切られたと感じやすい
寛容・観察者型0.4過程より結果を見る
効率・道具型0.9断言は確認の手間を省くための情報。外れると損失が直接大きい
礼節規範型0.7謙虚さの規範を重く見る
相棒・情緒型0.5関係の中で多少の強がりは許す

3.9 傷の減衰

信頼の傷は、出来事からのターン数で減ると仮定します。実際には実時間で減るはずですが、会話の記録から確実に取れる時間の目安がターン数なので、便宜としてターンで数えます。

  • t は、謝罪の対象になった失敗（またはその指摘）から最後の発話までのユーザー発話の数（turns_since_incident）。過去の指摘ごとの経過は incident_ages で別々に与えられる。
  • 傷が減ると、修復期の控えの必要量と、軽口・調子を急に戻す・許しの当然視の失点が小さくなる。約束破りはその回答の中の新しい違反なので減らない。
  • 20 という値と直線の形は仮説。population.json の timeline で変えられる。

4.3 文化についての注意

自信と誤り、信頼の修復の証拠は、多くが米国やシンガポールの参加者によるものです。日本の受け手での直接の証拠は、謝罪の機能（C-04）と謙遜（B-10、B-11）に限られます。日本の受け手に当てはまるかを人間の評価キット（8章）で確かめることが、この設計の最も大きな検証点です。

  • 日本の謝罪は「誰のせいか」より「相手の負担を認め、関係を保つこと」として働く。受け手モデルでは過失の承認と負担への言及を分けたまま扱い、米国の謝罪観（謝罪＝責任の承認）が混ざらないようにする。
  • 謙遜は文化に共通の価値。日本の受け手の特徴は、謙遜を好むことそのものではなく、強い謙遜を受け入れやすいという程度の違いとして、型の幅で表す。

5. 評価指標と検証の手続き

5.1 原則

  1. 予測を確率分布として定義し、真に適正なスコアリング規則で測る確率を正直に出したときに期待スコアが最良になる規則（Brier、対数損失、順位確率スコア）だけを主指標にする。
  2. 必ず基準と比べる定数の予測と条件だけの予測を同じ規則で採点し、スキルスコア（1 − 自分の損失 ÷ 基準の損失）で報告する。
  3. データを見て決めたものは、交差検証の外側で評価するパラメータの当てはめ、所属度関数の中心、設定の選択は、場面単位の交差検証の内側で行う。
  4. 不確かさは場面単位で見積もるブートストラップは場面単位（評定者が複数なら評定者×場面の二元）。二つの評価器の比較は、同じ再標本での差の区間で判断する。
  5. κ と「近さ」は記述用の副指標順位づけには使わない。

5.2 予測分布

シミュレータの主張は「受け手の母集団がこう分布する」なので、「無作為に選んだ評定者がどう答えるか」の予測分布を母集団から作ります。

【4値の評定】
P(k | μ)    = exp(β·μ_k) / Σ_j exp(β·μ_j)      （反応モデル。μ は受け手一人の所属度、β は所属度を選択に変える鋭さ）
p(k | 回答) = 母集団で平均した P(k | μ)        （β → ∞ が「最大の所属度を選ぶ」非ファジィ化）

【5段階の評定】
p(y | 回答, 述語) = 母集団で、受け手一人の所属度（＋評定者のノイズ σ）を5段階に丸めたときの割合

6. 観察者の集団

6.1 考え方

一回の観察は、観察者の分布から取った標本一つです。受け手を母集団として扱うのと同じく、観察者も集団として扱い、その平均を層Bに渡します。ただし、何を振るかには区別が要ります。読み手の態度を観察の側で振ると、層Bの性質と二重に数えることになるからです（P11）。

振るもの（観察の誤差・あいまいさ）

  • 観察方針の言い回し（字義どおり／文脈を補う／中立）
  • 本文から決まらない場面の事実（関係の上下・親疎、過失の明白さ、どこからが指摘か）の前提
  • モデルの系統（Claude／GPT／Gemini など）
  • 提示の仕方（単独で見せるか、順序、書式）
  • 同じ設定での繰り返し

振らないもの（受け手の違い。層Bの仕事）

  • 「怒っている受け手として読め」「寛容に読め」のような読み手の態度
  • 受け手の性質（当事者性、修復の重視など）

一文の悪い読みの指示にある「苛立っている受け手を仮定して」は観察の定義の一部なので、変えずに固定する。

6.2 変種

既定は、観察方針3水準 × モデルの系統2水準 = 6変種です。モデルの系統には、評価対象と別系統のモデルを必ず含めます。回答の提示順はランダムにし、同じ場面の回答は一つずつ見せます。本文から決まらない場面の事実には unknown を選べるようにし、集約では「票を投じない」として扱います。

6.4 観察の単位をそろえる（sim.py segment）

文の分割と成果物（コード・下書き）の切り出しをコードで行い、文に ID を付けて観察者に渡します。観察者は文 ID ごとに悪い読みと但し書きの種類を記録します。

6.5 観察者の評価と費用

  • 観察者間の一致（Krippendorff のα）、同じ変種での再観察の一致、観察方針とモデルの系統の主効果、集団の平均と各変種単独を5章の指標で比べた結果を報告する。
  • 192回答 × 6変種 ≈ 1,150回答分の観察。System One 経路では、質問の言い換えと選択肢の並べ替えで同じ集約ができる（System One）。

7. 較正と観察の固め

7.1 出どころごとの較正

population.json の judgment を、観察の出どころ（proxy、llm-ensemble、system-one）ごとに持てるようにし、観察JSONの source で切り替える。中心だけを、交差検証の内側で少数の人の評定から当てはめる。

7.2 場面の観察を固める

距離の変化のうち文量・絵文字・相槌化はコードで測り、観察者には丁寧語への切り替えと呼び方の正式化だけを問う。harm と prior_corrections は例を付けて定義を固め、信頼の傷では指摘の数に上限か強さの重みを付ける。

7.3 場面の中の判別力

条件で層別したスキルスコアと、場面の中の順位相関を報告する。取り違えの多い型（筆者が「足りない」・シミュレータが「釣り合う」）の回答を個別に読み、欠けている観察の欄を洗い出す。

9. 進める順序

  1. 評価指標と検証の手続き（5章）ほかの改善の効果を正しく測るために、最初に直す。
  2. 人間の評価キットと事前登録（8章）モデルを見ながら仮説を変えないために、控えのモデルより前に作る。
  3. 観察の単位の固定（6.4節）sim.py segment、observe_prompt.md。
  4. 観察者の集団（6章）sim.py observe --variants、sim.py ensemble。
  5. 控えの時間軸モデル（3章）observe_prompt.md、sim.py、population.json（overclaim）。
  6. 較正と観察の固め（7章）出どころ別の judgment。
  7. 人間のデータの収集と検証（8章）各段のあと、5章の手続きで評価し、検証の文書に記録する。

控えの時間軸（修復期）修復期24回答の Brier が v0.8 より良く、差の区間が 0 を含まない。修復期以外の成績を悪くしない
控えの時間軸（失敗の前の構え・但し書き）評価キットで H1〜H4・H7・H8 の向きを人間の評定が支持し、シミュレータの予測がその向きと一致する。ベンチマークの成績を悪くしない
観察者の集団集団の平均を使ったシミュレータの Brier が、各変種単独のどれにも負けない。LLM の観察での「釣り合う」の不足が半分以下になる
出どころごとの較正分割の外側で、較正なしより良い
全体「条件だけ」の基準に対するスキルスコアが正で、区間が 0 を含まない

11. 決定記録の案

ID決定
D-018受け手モデルに控えの時間軸を入れる。失敗の前の構え、謝罪の場面の構え、修復期の控えを観察し、局面の真理値で働きを切り替える。修復期は詫びではなく控えで中身を測る。謝罪の中身は過失の承認と負担への言及に分ける。過信を罰する度合いを受け手の性質 overclaim とする
D-019免責の但し書きを、種類（範囲の明示・確かめ・責任の限定）と局面（失敗の前・謝罪の場面・修復期）と回答の中の位置で働きを変える要素として扱う
D-020評価は、母集団から作った予測分布を真に適正なスコアリング規則で採点し、基準とのスキルスコアで報告する。データを見て決めるものは場面単位の交差検証の内側で決める。D-016 を改める
D-021層Aは、観察方針・場面の事実の前提・モデルの系統に幅を振った観察者の集団の平均とする。読み手の態度は振らない
D-022所属度関数の中心を、観察の出どころごとに較正する
D-023人間の評価キットを、操作した項目の組・ラテン方格の割り付け・仕組みを測る設問・事前登録した仮説の検定で、設計の仮説を確かめられるようにする
D-024信頼の傷は、出来事からのターン数で減衰する（20ターンで直線に消える。欺瞞の傷は半分が残る）。実際は実時間で減るが、便宜としてターンで数える

D-017 は System One への置き換えの案です。

12. 未解決の問い

  • 控えの必要量が関係の親疎でどう変わるか。親しい関係では、早めに普段の調子に戻ることがむしろ修復の合図になる可能性がある（H6 で一部を確かめる）。
  • 傷が何ターンで消えるか。いまは20ターンで直線に消えると仮定している（3.9節）。実際には実時間で減り、出来事の重さや関係でも変わるはず。
  • ユーザーが自分で確かめる手段を持っていたかで、失敗の前の控えめさや但し書きへの寛容さが変わる可能性がある。
  • AIの「確認済み」を実行記録と照合できる場合はコードで判定する。照合できない場合は観察者の集団の判断に任せる。
  • 但し書きが多すぎる場合（失敗の前でも何でも「念のためご確認ください」と言う）は、それ自体が負担や頼れなさになりうる。失敗が起きていない場面の評価は範囲の外だが、SHAZAI Rules の側で扱う価値がある。
  • 観察者の集団の平均でも、全変種が共有する系統的な偏りは残る。その場合は少数の人の観察で欄ごとに較正する。
  • 反応モデルの β が評定者ごとに違う場合、β を型の性質に加えるかどうか。
