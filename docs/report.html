このレポートは、ファジィ化する前の4値モデル（v0.4〜v0.7）の結果です。v0.8 から評定はファジィになり、受け手一人ひとりが「失礼／足りない／釣り合う／重すぎる」の4つの述語に所属度を持ちます（「足りない」は不足量だけから出します）。新しいモデルの作例の結果は 検証 2.1、仕組みは 仕組み 4章 を見てください。ベンチマークは v0.8 でまだ再計算していません。

受け手の分布で評価すると、条件の順位が筆者と一致した

LLMには回答に書かれていることを記録させるだけにし、良し悪しは、既存研究をもとに組んだ5つの受け手の型・1000人のシミュレーションで出す仕組みを作りました。SHAZAI Rules v0.4 ベンチマークの192回答で予備検証すると、条件の順位は筆者と一致し、筆者との一致度はLLMペルソナを上回りました。第6節では、信頼が損なわれやすく戻りにくい性質（信頼損傷ヒステリシス）を試作として組み込み、その効果と、今のベンチマークでは測りきれない理由を検討しています。第7節では、謝る側の態度・代償・場面の枠組み（現実のタスクか物語の中か）への拡張を作例で示しています。

観察（層A）：今回は代理観察。既存の84項目チェックと文面の特徴から作成し、一文ごとの悪い読みは含まない
受け手（層B）：5型の混合から1000人を抽出。型の比率と性質の強さは文献の向きから置いた事前値
データ：4モデル × 3条件 × 16場面 = 192回答。比較対象は筆者1名とLLMペルソナ3名の評定
注意：観察の規則と判定の定数は、このデータを見ながら調整した。一致度は甘めに出ており、乱数だけで±0.05程度揺れる

2. 仕組み

評価を二つの層に分けます。LLMの寛容さや、属性を演じたときに集団を平板にする癖は、層Aの「記録」までに閉じ込めます。どう受け取るかの多様性は、層Bのパラメータの分布として外から与えます。

1人の受け手の判定

① 不満の深さを感じる不満の明示度、調子の距離の変化（丁寧化・呼称・絵文字・文量・相槌化）、AI側の原因から、0〜4の深さ L を感じる。感度は人による
② 中身の不足を見るL に応じて必要な中身（詫び、冒頭での詫び、過失と負担の具体性）と、回答の中身を比べる
③ 失点を数える求められたことの未遂行、誤りの上塗り、弁解、相手への指摘、先を急ぐ、文体の崩れ、悪く読める一文など
④ 重さを見る詫びの回数、自己卑下、約束、許しの要求。明確な指摘の後の一度の詫びは過剰と見なさない

6. 信頼損傷ヒステリシス

信頼は損なわれやすく、戻りにくいものです。そのため同じ発話でも、そこに至るまでの経緯で受け取られ方が変わります。初回の作り込みではこの経路依存性が抜けていたので、受け手ごとに「傷 S」を持たせる形で試作しました。

違反を重ねるたびに、謝罪で戻る幅が小さくなる

概念図（シミュレータの出力ではない）。下がる時は一気に、戻る時は少しずつ。3回目の後は元の水準に戻りきらない

関連する研究と、シミュレータでの扱い

筆者の評定にも、経緯を前提にした判断が出ていた

筆者のコメントのうち約15件が、経緯を前提にしたものでした。前回、修復期だけ筆者が母集団の外にいたことも、謝罪を受け入れた後も傷が残っていると考えると説明がつきます。

SHAZAI Rules の「釣り合う」の割合（段階別）

謝罪の目減りをそのまま入れると、強い不満の場面で SHAZAI Rules の深い謝罪まで割り引かれる。格上げの変種で一部が戻る

    経緯を測るための場面設計

    今のベンチマークは各場面の経緯が1通りしかないので、経緯の効果を場面の違いと区別できません。経緯だけを変えた組が必要です。

    経緯違いの組最後の発話と回答を同じにして、経緯だけを変える。初回の軽い失敗／同じ失敗の3回目／虚偽を含む失敗／約束を破った後。評価者が同じ回答を別の評定にするか、対象AIが応答を変えるかを見る
    往路と復路の組同じ調子の発話に、悪化の途中で至った場合と、謝罪が受け入れられた後の回復の途中で至った場合を作る。ヒステリシスそのものの検査になる
    言葉と行動の組繰り返しの後に、言葉の謝罪だけの回答と、黙って直した回答を比べる。何度目からどちらが評価されるかを見る

    観察プロンプトには、AIが過去に謝った回数とその口調、破られた約束の回数を加えました。指標には、経緯の違いで評定と応答がどれだけ変わるか（経路差）を足します。

    SHAZAI Rules への示唆（未測定）

    • 同じ失敗を繰り返したら、謝罪を一段改める。同じ形の謝罪は割り引かれる（筆者のコメント「"ごめん"はもう受け付けられるフェーズではない」）
    • 一度約束を破った後は、新しい約束をしない。破られた約束の後の約束は、信頼をさらに下げる
    • 3度目は、言葉より黙って直すことを優先する。繰り返しの後は、どの修復策でも信頼が戻りきらない

    7. 態度・代償・場面の枠組みへの拡張

    謝る側の態度（しょんぼり、バツが悪そう、ショック、笑みなど）と代償、そして失敗が現実のタスクで起きたのか物語の中で起きたのかを、観察と受け手の規則に加えました。AIが示す仮想の身体や代償も扱います。下は、一点だけ変えた作例の組を1000人に通した結果です。台詞と観察はすべて作例です（examples/scenes.json）。

      設計の詳細と根拠は 設計・根拠 にあります。

      8. 限界と次の一手

      • 型の比率と性質の強さは、文献の向きから置いた事前値です。日本社会の分布の再現をうたうには、20〜30人程度の評定で型の混合を推定する必要があります。
      • 今回の観察は代理で、一文ごとの悪い読みを含みません。当事者性・修復の重視・寛容性は、今のデータでは特定できていません。シナリオ事実の一部は、筆者の評定を見た後に記入しています。
      • 次は OpenRouter のキーを設定し、python3 sim.py observe で層Aを独立に観察して、同じ検証をやり直します。
      • 最後の一文だけ違う、償いの有無だけ違う、といった最小限の差の回答対と、経緯だけを変えた場面の組（第6節）を作り、性質ごとに個別に測れるようにします。

      9. 実行方法

      python3 sim.py proxy runs/* -o out/obs-proxy.json          # 代理観察（API不要）
python3 sim.py observe runs/* -o out/obs-llm.json          # LLMで観察（OPENROUTER_API_KEY）
python3 sim.py simulate out/obs-llm.json runs/* -n 1000    # 母集団で評定分布
python3 sim.py fit out/obs-llm.json runs/* --seed 7        # 1人の評定者を再現するθ
python3 sim.py explain out/obs-llm.json runs/* --answer ID # 型ごとの判定理由
# 信頼損傷ヒステリシスと escalation は既定で有効（simulate / fit / explain / scenes 共通）
python3 sim.py simulate out/obs-llm.json runs/* --no-escalation  # 一段改めた謝罪も割り引く
python3 sim.py simulate out/obs-llm.json runs/* --no-hysteresis  # 傷 S を無効に
# 観察済みの場面の組（物語・AIキャラクター等）
python3 sim.py scenes examples/scenes.json -n 1000 -o out/scenes-result.json
